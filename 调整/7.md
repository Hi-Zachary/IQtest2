# V11 正式改进方案：Task-Isolated Dual-Branch Architecture

## 1. 当前问题的核心判断

经过 HCMI、TCAP、MSCM 三轮 Alignment 分支实验后，当前最重要的结论已经不是“Alignment 模块不够好”，而是：

> **DG-MPQ 与 Alignment 模块单独都有效，但在 Full 中由于梯度路径耦合，两个任务发生明显 negative transfer。**

split4 当前关键结果：

```text
B1 = DG-MPQ
Q-SRCC = 0.8641
A-SRCC = 0.7258
Joint  = 3.3512

B2 = MSCM
Q-SRCC = 0.8496
A-SRCC = 0.7434
Joint  = 3.3476

Full = DG-MPQ + MSCM
Q-SRCC = 0.8461
A-SRCC = 0.7267
Joint  = 3.3209
```

最关键的是：

```text
DG-MPQ 单独：Q 很强
MSCM 单独：A 很强
Full：Q 与 A 同时下降
```

因此：

```text
问题 ≠ DG-MPQ 无效
问题 ≠ MSCM 无效
问题 ≠ split 偶然性

问题 = Full 中两个任务的梯度耦合与表示耦合
```

V11 不再继续寻找新的 Alignment 模块。

正式保留：

```text
DG-MPQ
MSCM
```

并重构整个模型的数据流和梯度流。

---

## 2. V10 中真正的问题

当前 V10：

```python
v = v0 + DG_MPQ(...)

# Quality
h_q = quality_fusion([v, t0])

# Alignment
h_a = alignment_fusion([v, t0, a_corr])
```

问题在于：

```text
Alignment branch 也直接使用 DG-MPQ enhanced feature v
```

因此：

```text
L_A
 ↓
Alignment Head
 ↓
Alignment Fusion
 ↓
v
 ↓
DG-MPQ
```

Alignment loss 会直接反向更新 DG-MPQ。

所以虽然 DG-MPQ 被定义成：

```text
Quality Module
```

实际上它一直同时受到：

```text
L_Q + L_A
```

训练。

---

## 3. 为什么 B1 的 Alignment 本身就很高

B1 的结构实际是：

```text
Visual LoRA
     │
   DG-MPQ
     │
     v
   ┌─┴─┐
   │   │
   Q   A
```

因此 DG-MPQ 并不是“只服务 Quality”。

Alignment loss 也会改变：

```text
DG-MPQ
Visual LoRA
base_visual_proj
```

所以 B1 的：

```text
A-SRCC ≈ 0.726
```

并不意味着 DG-MPQ 天然擅长 Alignment。

它实际上已经被 Alignment supervision 共同优化。

这也是为什么后续再加 HCMI / TCAP / MSCM 时，第二模块很容易与原有 DG-MPQ representation 重叠甚至冲突。

---

## 4. V11 核心原则

> **Quality-specific parameters 只能被 Quality loss 更新。**

> **Alignment-specific parameters 只能被 Alignment loss 更新。**

唯一共享的部分：

```text
Frozen CLIP backbone
```

不再共享：

```text
Visual LoRA
Task-specific projections
Fusion
Heads
Task-specific modules
```

## 6. 第一层隔离：Alignment 不再使用 DG-MPQ 的 v

V10：

```python
h_a = alignment_fusion(
    torch.cat([
        v,
        t0,
        a_corr,
    ], dim=-1)
)
```

V11 改为：

```python
h_a = alignment_fusion(
    torch.cat([
        v_a,
        t_a,
        a_corr,
    ], dim=-1)
)
```

其中 `v_a` 来自 Alignment 自己的视觉 projection / LoRA-A。

不能再使用：

```text
v_q = DG-MPQ enhanced visual feature
```

---

## 7. 第二层隔离：Visual LoRA 拆成 LoRA-Q / LoRA-A

当前：

```text
一套 Visual LoRA
同时服务 Quality 和 Alignment
```

因此即使删除 Alignment 对 DG-MPQ 的直接依赖，仍然存在：

```text
L_Q → Visual LoRA
L_A → 同一套 Visual LoRA
```

两个任务仍会竞争 backbone adaptation 参数。

V11 改成：

```text
LoRA-Q → Quality branch
LoRA-A → Alignment branch
```

---

## 8. 为什么双 LoRA 成本可接受

当前 LoRA：

```text
Q/K projection
r = 4
alpha = 8
```

LoRA 参数量本身很小。

复制一套后，只增加很少 trainable parameters，但可以切断 adaptation-level gradient conflict。

相比此前 HCMI 约 2.53M 参数，这个代价很低。

## 9. Backbone 实现方式

不需要加载两个完整 CLIP。

仍然只保留一份：

```text

```

但 Attention 中维护两套 LoRA 参数：

```python

base weight frozen
+
lora_q_quality
+
lora_q_alignment

k_proj:
base weight frozen
+
lora_k_quality
+
lora_k_alignment
```

forward 时根据 branch 指定：

```python

    image,
    branch="quality"
)

vision_forward(
    image,
    branch="alignment"
)
```

即：

```text

```

## 14. Loss

保持：

$$
L = L_Q + L_A
$$

其中：

$$
L_Q = \mathrm{MSE}(\hat Q,Q)
$$

$$
L_A = \mathrm{MSE}(\hat A,A)
$$

但由于两条路径参数已经隔离：

`L_Q` 只能更新：

```text
LoRA-Q
quality_visual_proj
quality_text_proj
DG-MPQ
quality_fusion
quality_head
lambda_q
```

`L_A` 只能更新：

```text
LoRA-A
alignment_visual_proj
alignment_text_proj
MSCM
alignment_fusion
alignment_head
```

Frozen CLIP base 不更新。

## 17. Dual LoRA 接口设计

```python
class DualLoRALinear(nn.Module):

    def __init__(...):

        self.base = frozen_linear

        self.lora_q = LoRA(...)
        self.lora_a = LoRA(...)

    def forward(self, x, branch):

        y = self.base(x)

        if branch == "quality":
            y = y + self.lora_q(x)

        elif branch == "alignment":
            y = y + self.lora_a(x)

        return y
```

整个 ViT attention forward 时传递 `branch`。

## 18. V11 Forward 伪代码

```python
def forward(
    self,
    image,
    input_ids,
    attention_mask,
):

    # shared frozen text
    text_feat = self.backbone.encode_text(
        input_ids,
        attention_mask,
    )

    global_t = text_feat["global_t"]

    t_q = self.quality_text_proj(global_t)
    t_a = self.alignment_text_proj(global_t)

    # QUALITY
    feat_q = self.backbone.encode_image(
        image,
        lora_branch="quality",
    )

    hs_q = feat_q["vision_hidden"]
    global_v_q = feat_q["global_v"]

    v0_q = self.quality_visual_proj(global_v_q)

    delta_q = self.dg_mpq(
        hs_q[3],
        hs_q[6],
        hs_q[9],
        hs_q[12],
    )

    v_q = (
        v0_q
        + torch.tanh(self.lambda_q)
        * delta_q
    )

    h_q = self.quality_fusion(
        torch.cat([
            v_q,
            t_q,
        ], dim=-1)
    )

    q = self.quality_head(h_q)

    # ALIGNMENT
    feat_a = self.backbone.encode_image(
        image,
        lora_branch="alignment",
    )

    hs_a = feat_a["vision_hidden"]
    global_v_a = feat_a["global_v"]

    v_a = self.alignment_visual_proj(global_v_a)

    a_corr = self.mscm(
        hs_a[9][:, 1:, :],
        hs_a[12][:, 1:, :],
        t_a,
        global_v_a,
        global_t,
    )

    h_a = self.alignment_fusion(
        torch.cat([
            v_a,
            t_a,
            a_corr,
        ], dim=-1)
    )

    a = self.alignment_head(h_a)

    return torch.cat([
        q,
        a,
    ], dim=-1)
```

## 25. 更严格的判断规则

### 情况 A

```text
B1 Q 高
B2 A 高
Full 同时接近两者
```

说明 V11 成功，继续 split3/5/6。

### 情况 B

```text
B1 Q 高
B2 A 高
Full 仍两个都下降
```

如果已经完全参数隔离，那么问题就不再是 gradient conflict。

此时应检查：

```text
checkpoint criterion
batch-level loss scaling
data pipeline
shared text feature handling
implementation bug
```

而不是继续换模块。

### 情况 C

```text
V11 B1 Q 明显低于旧 B1
```

说明旧 B1 高 Q 的一部分收益其实来自 Alignment loss 对共享参数的辅助训练。

### 情况 D

说明旧 B2 中 Quality loss 对共享 LoRA 提供了辅助 regularization。

## 26. 如果硬隔离过头：第二阶段 Soft Sharing

只有 V11 Hard Isolation 验证后，才考虑 Soft Sharing。

例如：

$$
L_{share}
=
\|\theta_Q-\theta_A\|_2^2
$$

总损失：

$$
L
=

+
L_A
+
\lambda_s L_{share}
$$

即：

```text

但保持一定相关性
```

第一版不要加。

## 29. Task-Isolated Architecture 是否算第三贡献

不建议。

V11 的：

```text
Dual LoRA
Task-Specific Projection
Task-Specific Fusion
Strict Branch Isolation
```

统一作为：

```text
task-oriented architecture / implementation framework
```

论文中可以描述：

> To avoid negative transfer between the heterogeneous quality and alignment objectives, the two task-specific branches use independent lightweight adaptation and prediction pathways while sharing the frozen CLIP foundation.

但不单独列 Contribution。

## 30. 最终方法故事

```text
AIGC Quality Assessment
包含两个性质不同的目标：

Perceptual Quality
→ intra-modal visual degradation

Image-Text Alignment
→ cross-modal semantic correspondence
```

因此：

```text
DG-MPQ
建模 visual ↔ visual deviation

MSCM
建模 visual ↔ text correspondence
```

由于两种监督目标不同：

```text
使用 task-isolated lightweight adaptation
避免 negative transfer
```

完整逻辑：

```text
Task Difference
      ↓
Task-specific Modeling
      ↓
Task-isolated Adaptation
      ↓
Dual Score Prediction
```

## 33. 必须做的梯度检查

V11 第一次训练前建议加一次 debug。

先：

```python
loss_q.backward(retain_graph=True)
```

检查：

```text
DG-MPQ grad != 0
LoRA-Q grad != 0

MSCM grad == 0
LoRA-A grad == 0
```

清梯度后再：

```python
loss_a.backward()
```

检查：

```text
MSCM grad != 0
LoRA-A grad != 0

DG-MPQ grad == 0
LoRA-Q grad == 0
```

如果不是这样，说明分支仍然没有真正隔离。

## 35. 一句话总结

V11 不再继续更换 DG-MPQ 或 MSCM，而是解决真正导致 Full 失败的系统级问题：当前 Alignment loss 会通过共享视觉表示与 LoRA 反向影响 DG-MPQ，使两个异质任务产生明显 negative transfer。V11 将 Frozen CLIP 作为唯一共享基础，分别配置 LoRA-Q / LoRA-A、task-specific projection、DG-MPQ / MSCM 和独立 fusion/head，使 Quality loss 只能更新 Quality branch、Alignment loss 只能更新 Alignment branch，从而尽量同时保留 DG-MPQ 的 Q 优势和 MSCM 的 A 优势。
