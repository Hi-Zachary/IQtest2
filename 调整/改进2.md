# V8-Slim 精简方案

> 目标：在尽量保留当前 V8 已验证增益的前提下，减少“模块堆叠感”、降低参数量、缩短方法链路，并让论文/答辩叙事更清楚。
>
> 当前依据：commit `9f54c1e4d227a664cd85f523f515c6037740aecd` 的五组完整训练日志与 v8 分支现有实现。

---

## 1. 当前 V8 的真实结构

当前模型可以概括为：

```text
CLIP ViT-B/16
  + Visual LoRA
  + DG-MPQ
  + DP-HCMI-ViT
  + shared fusion
  + dual heads
```

论文/答辩中不要说“3 个创新模块”。

更合适的表述：

- Visual LoRA：backbone adaptation / PEFT，不作为创新点；
- DG-MPQ：Quality-oriented 主模块；
- HCMI-ViT：Alignment-oriented 主模块。

即：

```text
CLIP ViT-B/16 + lightweight LoRA adaptation
          +
    two task-oriented modules
      ├─ DG-MPQ
      └─ HCMI-ViT
```

这样整体方法从一开始就不会显得是“三个大模块硬缝”。

---

## 2. 当前消融结果说明了什么

统一看各自 best-joint checkpoint：

| Variant | Q-SRCC | Q-PLCC | A-SRCC | A-PLCC |
|---|---:|---:|---:|---:|
| B0 Frozen ViT | 0.8089 | 0.8859 | 0.6608 | 0.8214 |
| R0 + Visual LoRA | 0.8388 | 0.9061 | 0.6912 | 0.8380 |
| B1 + DG-MPQ | 0.8539 | 0.9138 | 0.7045 | 0.8426 |
| B2 + DP-HCMI | 0.8441 | 0.9083 | 0.7037 | 0.8419 |
| Full | 0.8543 | 0.9147 | 0.7147 | 0.8467 |

关键结论：

1. **LoRA 明确有效**，R0 相对 B0 四项指标都有显著提升；
2. **DG-MPQ 明确有效**，R0 → B1 的 Q-SRCC 约 +0.015；
3. **DP-HCMI 整体有效**，R0 → B2 的 A-SRCC 约 +0.012；
4. **Full 没有明显负交互**，加入 DP-HCMI 后基本保住 B1 的 Quality，同时 A-SRCC 再提升约 +0.010；
5. 因此当前不应推翻 V8，而应在已经有效的框架内做“有证据的精简”。

---

## 3. 精简原则

只动三类东西：

1. **训练日志已经显示几乎没发挥作用的组件；**
2. **参数量很大但目前没有对应独立证据的组件；**
3. **功能明显重复、只是 donor 模块遗留的组件。**

不优先动：

- Visual LoRA 主体；
- DG-MPQ 主链；
- detail / semantic 两层级结构；
- hierarchy gate；
- outer residual gate；
- shared fusion 与双头预测。

---

# 4. 直接确定的 V8-Slim 结构

建议最终先收缩为：

```text
CLIP ViT-B/16
  + Visual LoRA
      q_proj + k_proj
      r = 4
      alpha = 8
      dropout = 0

  + DG-MPQ
      multi-level patches: L3 / L6 / L9 / L12
      semantic deviation
      patch weighting
      weighted aggregation
      residual injection

  + HCMI-ViT
      detail-level: L6
      semantic-level: L12
      prompt weighting
      bidirectional cross-modal interaction
      compact per-level MLP
      adaptive hierarchy fusion
      residual injection

  + shared fusion
  + dual regression heads
```

相较当前 V8，核心变化只有三处：

```text
1. 删除 discrepancy-guided attention bias
2. LoRA dropout 0.05 → 0
3. HCMI 的 mlp_ratio 2.0 → 1.0
```

另外再对 MSA-T 做一次最小验证，决定是否彻底删掉。

---

# 5. 第一优先级：删除 discrepancy-guided attention bias

## 5.1 当前实现

当前 DP-HCMI 中有：

```python
D = 1 - cosine(V, T)
bias = -tanh(beta_align) * D
attention_logits += bias
```

对应：

```text
_discrepancy()
beta_align
bias_d
bias_s
CrossAttention(attn_bias=...)
```

## 5.2 为什么大概率可以删

当前日志里：

```text
B2 best-joint:
beta_align ≈ 0.0032

Full best-joint:
beta_align ≈ 0.0022
```

而同时：

```text
Full align_ratio ≈ 0.149
```

说明：

- 整个 HCMI branch 是活的；
- 但 discrepancy bias 自己的 gate 几乎为 0；
- 当前 HCMI 的收益大概率主要来自 hierarchical cross-modal interaction，而不是 discrepancy bias。

## 5.3 直接修改

删除：

```python
self.use_align_bias
self.beta_align
_discrepancy()
disc_d
disc_s
bias_d
bias_s
```

CrossAttention 调用改为：

```python
V_d = detail_base + self.alpha_d * self.detail_cross_v(
    detail_base,
    T_e,
    mask=text_mask,
)

V_s = semantic_base + self.alpha_s * self.semantic_cross_v(
    semantic_base,
    T_e,
    mask=text_mask,
)
```

如果 `attention.py` 里的 `attn_bias` 只给本项目这里使用，也可以继续把该接口删掉。

## 5.4 命名同步修改

删掉 discrepancy 后，不要再继续使用 `DP-HCMI` 这个名字。

建议改名：

```text
HCMI-ViT
Hierarchical Cross-Modal Interaction for ViT
```

或者：

```text
P-HCMI-ViT
Prompt-conditioned Hierarchical Cross-Modal Interaction for ViT
```

更推荐第一种，最干净。

---

# 6. 第二优先级：LoRA dropout 改为 0

当前配置：

```text
r = 4
alpha = 8
dropout = 0.05
target = q_proj + k_proj
```

但当前 `model_v8.py` 的 `train()` 会在 `freeze_visual=True` 时执行：

```python
self.backbone.clip.vision_model.eval()
```

LoRA 就包在 `vision_model` 里，所以现有训练中 LoRA dropout 实际处于关闭状态。

因此当前好结果事实上更接近：

```text
LoRA dropout = 0
```

直接把配置改为：

```yaml
lora_dropout: 0.0
```

这一步不会改变当前实际训练行为，只是让配置和真实行为一致。

Visual LoRA 本体不要继续砍：

```text
不要改成 only-q
不要改 r=2
不要去掉 k_proj
```

因为 LoRA 是目前收益/参数比最高的部分。

---

# 7. 第三优先级：HCMI 的 MLP 缩小一半

当前每个 level：

```text
input: 2D = 512
hidden: 2D * mlp_ratio = 1024
output: D = 256
```

即：

```text
512 → 1024 → 256
```

detail 和 semantic 各一套。

建议：

```yaml
mlp_ratio: 1.0
```

变成：

```text
512 → 512 → 256
```

优点：

- 不改变 HCMI 的任何核心结构；
- detail / semantic hierarchy 仍在；
- cross-attention 仍在；
- hierarchy gate 仍在；
- 只是把过宽的 FFN 收窄；
- 预计可减少约 0.79M 可训练参数。

这属于“低风险结构压缩”。

---

# 8. 最值得验证后再删：MSA-T 多核文本增强

## 8.1 当前结构

当前 text token 在进入 cross-modal interaction 前，还经过：

```text
Conv1d k=3
Conv1d k=5
Conv1d k=7
concat
1×1 Conv
GELU
```

然后：

```python
T_e = T + eta * MSA_T(T)
```

## 8.2 为什么高度可疑

它有几个问题：

1. CLIP text token 本身已经经过 Transformer contextualization；
2. 后面马上还有 prompt weighting；
3. 后面还有双向 cross-attention；
4. multi-kernel Conv 在这里有明显的 donor-module 遗留感；
5. 这一块参数量约 1.18M，比整个 DG-MPQ 都大；
6. 当前日志没有记录 `eta`，我们甚至不知道训练后这 1.18M 参数到底被 residual gate 使用到了多少。

因此 MSA-T 是当前最值得做一次单独 on/off 验证的部分。

## 8.3 不要直接猜，先跑一个实验

已有配置开关：

```yaml
dphcmi_use_multi_kernel: false
```

跑：

```text
Full-Slim-A:
LoRA + DG-MPQ + HCMI
- discrepancy bias
- MSA-T
mlp_ratio = 1
```

如果相对保留 MSA-T 的版本：

```text
A-SRCC 下降 <= 0.002 ~ 0.003
且 Q 基本不变
```

建议直接永久删除 MSA-T。

如果掉得明显，例如：

```text
A-SRCC 下降 >= 0.005
```

则保留。

# 9. Prompt Weighting：先保留，不急着删

当前：

```python
score = prompt_gate(T)
weight = softmax(score)
weight = weight * valid_len
T = T * weight
```

它和后面的 cross-attention 在功能上确实有一定重叠：

```text
prompt gate 在选 token
cross-attention 也在选 token
```

但 prompt gate 本身参数量很小，所以第一轮没有必要为了省参数删掉。

当前 `prompt_w_mean` 日志几乎没有解释力，因为把 padding token 一起平均以后，它主要反映的是有效 token 比例。

建议把 logging 改为：

```text
prompt_w_valid_std
prompt_w_max
prompt_w_entropy
```

只在 valid tokens 内统计。

如果后续发现：

```text
valid_std 很小
entropy 接近 uniform
```

再考虑删 prompt weighting。

---

# 10. Hierarchy Gate：保留

不要删 hierarchy gate。

原因是日志已经证明它不是一个恒定装饰：

```text
B2 best-joint:
hier_gate ≈ 0.861

Full best-joint:
hier_gate ≈ 0.518
```

也就是说：

- B2 单独时更依赖 detail branch；
- Full 中 detail / semantic 使用趋于均衡；
- gate 会根据联合结构学到不同融合策略。

所以：

```text
L6 detail
+
L12 semantic
+
adaptive hierarchy gate
```

应该保留为 HCMI 的核心结构。

---

# 11. DG-MPQ：第一轮不要砍核心

DG-MPQ 当前最有独立证据：

```text
R0 Q-SRCC = 0.8388
B1 Q-SRCC = 0.8539
提升约 +0.0151
```

而且 patch weight：

```text
训练初期：
mean ≈ 0.49
std  ≈ 0.014

训练后：
mean ≈ 0.15
std  ≈ 0.10
```

说明 weighting 确实学出了明显区分度。

因此第一轮保留完整：

```text
L3 / L6 / L9 / L12 multi-level patch
semantic deviation
patch weighting
weighted aggregation
quality residual
```

# 12. DG-MPQ 的第二阶段可选精简

如果完成 HCMI 精简后还想继续压缩，再考虑 DG-MPQ projection sharing。

当前：

```text
H3  -> LN + Linear_3
H6  -> LN + Linear_6
H9  -> LN + Linear_9
H12 -> LN + Linear_12
CLS  -> LN + Linear_g
```

五套不同 projection 后再算 cosine deviation。

可以改为：

```text
H3  -> LN3  ┐
H6  -> LN6  ├─ shared Linear(768 -> 256)
H9  -> LN9  ┤
H12 -> LN12 ┤
CLS -> LNG   ┘
```

优点：

1. 参数量明显下降；
2. patch 与 global anchor 真正进入同一 projection space；
3. cosine semantic deviation 的解释反而更合理。

但是：

**这一步不要和 HCMI 第一轮瘦身一起做。**

因为 DG-MPQ 当前已经表现良好，应该避免同时改两个主模块导致无法判断是哪一处造成性能变化。

# 16. 论文/答辩叙事同步简化

推荐最终只讲两件事：

## Contribution 1：AIGC 局部质量建模

```text
multi-level ViT patch features
+
local-global semantic deviation
+
deviation-guided patch aggregation
```

对应 DG-MPQ。

## Contribution 2：细粒度图文层级交互

```text
prompt-aware text representation
+
detail/semantic visual hierarchy
+
bidirectional cross-modal interaction
+
adaptive hierarchy fusion
```

对应 HCMI-ViT。

Visual LoRA 只作为：

```text
lightweight CLIP adaptation for AIGC-IQA
```

不作为创新点。

这样整套方法从叙事上就是：

```text
一个负责局部视觉质量
+
一个负责细粒度图文一致性
+
LoRA 负责让 Frozen CLIP 更适应 AIGC-IQA
```

足够完整，也不会显得堆模块。

# 17. 最终决策

当前建议不是“重做 V8”，而是：

```text
保留框架
保留两个主模块
删除无证据的内部装饰
缩窄过宽的 FFN
对最重的 donor 子模块做一次 on/off 验证
```

推荐执行顺序：

```text
第一步：删 discrepancy bias
第二步：mlp_ratio 2 -> 1
第三步：LoRA dropout 写成 0
第四步：跑 S1
第五步：跑 no-MSA 的 S2
第六步：根据 S2 决定是否永久移除 MSA-T
```

如果 S1/S2 能把 Full 保持在大约：

```text
Q-SRCC ≈ 0.851 ~ 0.855
A-SRCC ≈ 0.710 ~ 0.715
```

那么 V8-Slim 就比当前 V8 更适合作为最终方案：

- 参数更少；
- 结构更容易解释；
- 两个创新点边界更清晰；
- donor module 痕迹更弱；
- 消融逻辑更干净；
- 面试/答辩时更容易讲清楚为什么每一部分存在。
