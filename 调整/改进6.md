# V10 正式改进方案：DG-MPQ + MSCM

## 1. 方案结论

V9 的 TCAP 已经可以停止继续优化。当前实验表明，TCAP 的 attention 长期接近均匀分布（约 $1/196$），因此没有学到有效的 prompt-conditioned patch retrieval。

V10 不再使用 Cross-Attention / Prompt Gate / Hierarchy Gate / Text-conditioned Attention Pooling，而改为直接利用 CLIP 已经学习好的视觉—文本相似度空间。

正式采用第二模块：

**MSCM — Multi-Level Semantic Correspondence Modeling**

中文：**多层语义对应建模模块**

核心思想：

> Image-Text Alignment 的本质不是重新生成跨模态特征，而是判断文本语义与图像内容之间的对应程度。因此，V10 直接在多个 ViT 高层语义层上构造 patch-wise image-text correspondence maps，并结合 CLIP global similarity，通过轻量空间融合建模局部与全局语义一致性。

最终两个核心模块：

```text
DG-MPQ
→ Perceptual Quality

MSCM
→ Image-Text Alignment
```


## 3. 显式 Semantic Correspondence

此前两个 Alignment 模块：

```text
HCMI:
双向 Cross-Attention

TCAP:
Text → Image Cross-Attention
```

都依赖网络自行学习“哪些视觉区域应该与文本发生交互”。

V10 改为直接计算：

$$
s_i^{(l)}
=
\frac{
v_i^{(l)} \cdot t
}{
\|v_i^{(l)}\|_2 \|t\|_2
}
$$

其中：

- $v_i^{(l)}$：第 $l$ 层第 $i$ 个视觉 patch token；
- $t$：文本全局语义表示；
- $s_i^{(l)}$：该 patch 与 prompt 的语义对应程度。

这样不要求模型重新学习 alignment geometry，而是直接利用 CLIP 已经训练好的视觉—语言匹配空间。

---

## 4. MSCM 输入层选择

推荐使用：

```text
H9
H12
```

而不是 H6 + H12。

原因：

- H9 更偏 object-level semantics、区域语义和中高层组合关系；
- H12 更偏高层语义与全局抽象。

Alignment 主要关注 object existence、attribute correctness、semantic composition 和 prompt consistency，因此 H9 + H12 更合适。

## 8. Patch-wise Semantic Correspondence Map

```python
S9 = (V9_n * T.unsqueeze(1)).sum(dim=-1)
S12 = (V12_n * T.unsqueeze(1)).sum(dim=-1)
```

得到：

```text
S9  : [B,196]
S12 : [B,196]
```

reshape：

```python
S9 = S9.view(B, 1, 14, 14)
S12 = S12.view(B, 1, 14, 14)
```

含义：

```text
S9  → 中高层局部语义是否与 prompt 对应
S12 → 高层语义区域是否与 prompt 对应
```

---

## 9. 为什么 Patch-wise Similarity 比 Global Similarity 更重要

global cosine 只能表示整张图总体上与 prompt 的相似程度，但很多 AIGC alignment 错误是局部的。

例如：

```text
prompt:
"A man holding a red umbrella beside a dog."
```

图像可能：

```text
man       √
umbrella  √
red       ×
dog       ×
```

整体 global similarity 仍可能较高。

patch-wise correspondence map 可以保留局部 mismatch，因此 MSCM 的重点是：

> Multi-Level Local Semantic Correspondence.

---

## 10. Multi-Level Correspondence Fusion

```python
S = torch.cat([S9, S12], dim=1)
```

得到：

```text
[B,2,14,14]
```

然后：

```python
self.spatial_fusion = nn.Sequential(
    nn.Conv2d(2, 32, kernel_size=3, padding=1),
    nn.GELU(),
    nn.Conv2d(32, 64, kernel_size=3, padding=1),
    nn.GELU(),
)
```

得到：

```text
F_corr ∈ R^(B×64×14×14)
```

3×3 Conv 用于建模相邻区域的 correspondence pattern，而不是孤立 patch 的单点 similarity。

## 11. Local Correspondence Descriptor

```python
f_local = torch.cat([f_mean, f_max], dim=-1)
```

```text

```

含义：

```text

```

## 12. Global Correspondence Cue

保留 CLIP 原始 global similarity：

```python
g_v = F.normalize(global_v, dim=-1)
g_t = F.normalize(global_t, dim=-1)

s_global = (g_v * g_t).sum(dim=-1, keepdim=True)
```

这里优先使用 CLIP 原始 projection space，而不是经过 base_visual_proj / base_text_proj 后的 256D 特征。

额外保留：

```python
s9_mean  = S9.flatten(1).mean(dim=1, keepdim=True)

s12_mean = S12.flatten(1).mean(dim=1, keepdim=True)
```

## 18. 推荐 MSCM 实现

```python
class MSCM(nn.Module):

    def __init__(
        self,
        visual_width=768,
        dim=256,
        spatial_dim=64,
        drop=0.1,
    ):
        super().__init__()

        self.proj9 = nn.Sequential(
            nn.LayerNorm(visual_width),
            nn.Linear(visual_width, dim),
        )

        self.proj12 = nn.Sequential(
            nn.LayerNorm(visual_width),
            nn.Linear(visual_width, dim),
        )

        self.spatial_fusion = nn.Sequential(
            nn.Conv2d(2, 32, 3, padding=1),
            nn.GELU(),
            nn.Conv2d(32, spatial_dim, 3, padding=1),
            nn.GELU(),
        )

        corr_dim = spatial_dim * 2 + 7

        self.corr_proj = nn.Sequential(
            nn.Linear(corr_dim, dim),
            nn.GELU(),
            nn.Dropout(drop),
            nn.LayerNorm(dim),
        )

    def forward(
        self,
        h9,
        h12,
        t0,
        global_v,
        global_t,
    ):

        B = h9.shape[0]

        V9 = F.normalize(self.proj9(h9), dim=-1)
        V12 = F.normalize(self.proj12(h12), dim=-1)
        T = F.normalize(t0, dim=-1)

        S9 = (V9 * T.unsqueeze(1)).sum(dim=-1)
        S12 = (V12 * T.unsqueeze(1)).sum(dim=-1)

        S9_map = S9.view(B, 1, 14, 14)
        S12_map = S12.view(B, 1, 14, 14)

        S = torch.cat([S9_map, S12_map], dim=1)
        Fcorr = self.spatial_fusion(S)

        f_mean = Fcorr.mean(dim=(2, 3))
        f_max = Fcorr.amax(dim=(2, 3))

        s9_mean = S9.mean(dim=1, keepdim=True)
        s9_max = S9.amax(dim=1, keepdim=True)
        s9_min = S9.amin(dim=1, keepdim=True)

        s12_mean = S12.mean(dim=1, keepdim=True)
        s12_max = S12.amax(dim=1, keepdim=True)
        s12_min = S12.amin(dim=1, keepdim=True)

        gv = F.normalize(global_v, dim=-1)
        gt = F.normalize(global_t, dim=-1)

        s_global = (gv * gt).sum(dim=-1, keepdim=True)

        corr = torch.cat([
            f_mean,
            f_max,
            s9_mean,
            s9_max,
            s9_min,
            s12_mean,
            s12_max,
            s12_min,
            s_global,
        ], dim=-1)

        return self.corr_proj(corr)
```

## 19. V10 Forward

```python
feat = backbone(
    x,
    input_ids,
    attention_mask,
)

global_v = feat["global_v"]
global_t = feat["global_t"]
hs = feat["vision_hidden"]

v0 = base_visual_proj(global_v)
t0 = base_text_proj(global_t)

# DG-MPQ
delta_q = dg_mpq(
    hs[3],
    hs[6],
    hs[9],
    hs[12],
)

v = v0 + torch.tanh(lambda_q) * delta_q

# MSCM
a_corr = mscm(
    hs[9][:, 1:, :],
    hs[12][:, 1:, :],
    t0,
    global_v,
    global_t,
)

# Quality
h_q = quality_fusion(
    torch.cat([v, t0], dim=-1)
)
q = quality_head(h_q)

# Alignment
h_a = alignment_fusion(
    torch.cat([v, t0, a_corr], dim=-1)
)
a = alignment_head(h_a)

return torch.cat([q, a], dim=-1)
```

## 20. 参数量控制

MSCM 主要包含：

```text
H9 projection
H12 projection
Spatial Fusion
Correspondence Projection
```

总参数量预计低于 0.5M，明显低于 HCMI（约 2.53M）和 TCAP（约 0.79M）。

---

## 21. 为什么这个复杂度合适

MSCM 不是“两个 cosine + MLP”，而是包含三个层次：

```text
Level 1 — Patch Correspondence
H9 patch ↔ text
H12 patch ↔ text

Level 2 — Spatial Correspondence
multi-level similarity maps
→ convolutional spatial modeling

Level 3 — Global Correspondence
CLIP global image-text similarity
+
multi-level map statistics
```

因此完整建模：

```text
local + spatial + global
```

三个层次的 Alignment 信息。

---

## 22. 与 DG-MPQ 的互补性

DG-MPQ：

```text
visual ↔ visual
```

关注：

```text
局部视觉是否偏离整体视觉语义
```

用于 Perceptual Quality。

MSCM：

```text
visual ↔ text
```

关注：

```text
局部和全局视觉语义是否与文本一致
```

用于 Image-Text Alignment。

因此：

```text
DG-MPQ = Intra-modal visual deviation
MSCM   = Cross-modal semantic correspondence
```

## 28. 如何解释 B2 / Full 结果

如果：

```text
B2-MSCM Alignment > B1 Alignment
```

说明显式 semantic correspondence 本身确实提供额外 alignment information。

如果：

```text
B2 > B1 on A
但 Full < B2
```

则问题主要是 multi-task / shared backbone gradient coupling，而不是 MSCM 模块无效。

如果：

```text
B2-MSCM A <= B1 A
```

则说明当前 B1 中 CLIP global representation + DG-MPQ + LoRA 已经覆盖了大部分可利用的 Alignment 信息。

这时不建议再设计第三个 alignment feature module，应转向：

```text
Task-Differentiated Adaptation
```

或者：

```text
Multi-modal Prompt Learning
```

作为第二主贡献。

## 31. 一句话总结

V10 使用 Multi-Level Semantic Correspondence Modeling 替代 HCMI 和 TCAP：直接在 CLIP ViT 的 H9/H12 patch token 与文本语义之间构造显式 patch-wise similarity maps，通过轻量卷积建模空间 correspondence，并融合多层局部统计与原始 CLIP global similarity，从而形成一个同时包含 local、spatial 和 global image-text correspondence 的 Alignment representation；DG-MPQ 继续独立负责 perceptual quality，最终形成清晰的 Visual-Visual / Visual-Text 双分支建模框架。
