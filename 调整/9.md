# V13 改进方案：Shared-LoRA Gradient Conflict Mitigation

## 1. 当前结论

经过 V11.1 matched-init control 与 V12 partial sharing 实验后，当前问题已经可以明确定位：

```text
不是初始化问题
不是隐藏参数共享 bug
不是 DG-MPQ / MSCM 直接 feature coupling
```

V11.1 已验证：

```text
Full-Q == B1-Q
Full-A == B2-A
```

在 hard isolation 条件下逐 epoch 可以做到：

```text
deltaQ = 0
deltaA = 0
```

说明此前 V11 的 Full 下降主要来自初始化与随机训练轨迹差异。

V12 改为：

```text
Shared Visual LoRA
+
DG-MPQ only for Quality
+
MSCM only for Alignment
+
independent projections / fusion / heads
```

之后 split4：

| Model | Q-SRCC | A-SRCC | Joint |
|---|---:|---:|---:|
| R0 | 0.8661 | 0.7321 | 3.3594 |
| B1 = R0 + DG-MPQ | **0.8775** | 0.7269 | **3.3731** |
| B2 = R0 + MSCM | 0.8526 | **0.7328** | 3.3389 |
| Full | 0.8605 | 0.7309 | 3.3494 |

关键现象：

```text
B2 开启 MSCM 后：
Q 从 0.8661 -> 0.8526

Full 相比 B1：
Q 从 0.8775 -> 0.8605
```

但 MSCM 并不进入 Quality forward。

因此剩余唯一合理的耦合点是：

```text
Shared Visual LoRA
```

即：

```text
L_Q 和 L_A 同时更新 Shared LoRA
```

当前最可能的问题：

> Quality 与 Alignment 在 Shared LoRA 参数空间中存在 gradient conflict。

---

## 2. V13 核心目标

V13 不再换模块。

继续保留：

```text
DG-MPQ
MSCM
Shared Visual LoRA
```

仅修改 shared LoRA 的优化方式：

```text
普通梯度求和
        ↓
PCGrad
```

目标：

> 保留 shared LoRA 带来的跨任务 positive transfer，同时减少 Q/A 两个任务在共享适配参数上的 destructive gradient interference。

## 4. 第一阶段：Gradient Conflict Diagnosis

对于 Shared LoRA 参数 $\theta_s$，分别计算：

$$
g_Q = \nabla_{\theta_s} L_Q
$$

$$
g_A = \nabla_{\theta_s} L_A
$$

计算 cosine similarity：

$$
\operatorname{cos}(g_Q,g_A)
=
\frac{
g_Q^\top g_A
}{
\|g_Q\|_2\|g_A\|_2+\epsilon
}
$$

如果：

$$
\operatorname{cos}(g_Q,g_A)<0
$$

则说明两个任务在 Shared LoRA 上存在梯度冲突。

---

## 5. 推荐日志

每隔 20 batches 记录：

```text
grad_cos
grad_q_norm
grad_a_norm
```

每个 epoch 统计：

```text
mean_grad_cos
conflict_rate
mean_grad_q_norm
mean_grad_a_norm
```

其中：

$$
\text{conflict rate}
=
\frac{
\#\{\operatorname{cos}(g_Q,g_A)<0\}
}{
\#\text{batches}
}
$$

例如：

```text
epoch=0
grad_cos=-0.182
grad_q_norm=0.431
grad_a_norm=0.388
conflict_rate=0.64
```

如果前 5~10 epoch 大量出现：

```text
grad_cos < 0
```

则基本可以确认 shared-LoRA-level gradient conflict。

---

## 6. PCGrad 原理

对于两个任务梯度：

```text
g_Q
g_A
```

若：

$$
g_Q^\top g_A < 0
$$

则将冲突部分投影掉。

对 Quality：

$$
g_Q'
=
g_Q
-
\frac{
g_Q^\top g_A
}{
\|g_A\|_2^2+\epsilon
}
g_A
$$

对 Alignment：

$$
g_A'
=
g_A
-
\frac{
g_A^\top g_Q
}{
\|g_Q\|_2^2+\epsilon
}
g_Q
$$

最后 Shared LoRA 更新梯度：

$$
g_s
=
g_Q'
+
g_A'
$$

若：

$$
g_Q^\top g_A \ge 0
$$

则：

$$
g_s = g_Q + g_A
$$

---

## 7. 为什么只对 Shared LoRA 使用 PCGrad

不要对整个模型使用 PCGrad。

因为：

```text
DG-MPQ 和 MSCM 本来就不共享参数
Q/A projection/fusion/head 也不共享
```

真正发生任务梯度竞争的只有：

```text
Shared Visual LoRA
```

因此 V13 采用：

```text
Selective PCGrad
```

即：

```text
PCGrad only on Shared LoRA
```

优点：

```text
1. 改动小
2. 不影响两个 task-specific module 的正常学习
3. 方法解释清楚
```

## 9. 推荐训练流程

每个 batch：

```python
optimizer.zero_grad()

pred = model(image, text)

q_pred = pred[:, 0]
a_pred = pred[:, 1]

loss_q = mse(q_pred, q_gt)
loss_a = mse(a_pred, a_gt)
```

分别求 Shared LoRA 梯度：

```python
gq = torch.autograd.grad(
    loss_q,
    shared_params,
    retain_graph=True,
    allow_unused=True,
)

ga = torch.autograd.grad(
    loss_a,
    shared_params,
    retain_graph=True,
    allow_unused=True,
)
```

然后分别求 task-specific 参数梯度：

```python
gq_task = torch.autograd.grad(
    loss_q,
    quality_params,
    retain_graph=True,
    allow_unused=True,
)

ga_task = torch.autograd.grad(
    loss_a,
    alignment_params,
    retain_graph=False,
    allow_unused=True,
)
```

最后：

```text
quality_params.grad = gq_task
alignment_params.grad = ga_task
shared_params.grad = PCGrad(gq, ga)
```

再：

```python
optimizer.step()
```

## 11. V13-A 判定

### 情况 A：冲突明显

例如：

```text
mean grad cosine < 0
```

或：

```text
conflict rate > 40%
```

则进入：

```text
V13-B PCGrad
```

### 情况 B：大部分梯度同向

例如：

```text
mean grad cosine > 0.2
conflict rate < 10%
```

则 Shared LoRA gradient conflict 不是主要原因。

此时不要硬上 PCGrad，而应重新判断 MSCM 本身是否提供了足够有效的信息。

## 15. 如果 PCGrad 有效

若：

```text
Q:
0.8605 -> 0.873+

A:
仍保持 0.730+
```

说明主要问题确实来自 Shared LoRA gradient interference。

此时保留：

```text
DG-MPQ
MSCM
Shared LoRA
Selective PCGrad
```

作为最终框架。

---

## 16. 如果 PCGrad 只恢复 Q，但 A 增益仍极小

例如：

```text
B1:
Q = 0.8775
A = 0.7269

Full-PCGrad:
Q = 0.875
A = 0.728
```

则说明：

```text
优化冲突解决了
但 MSCM 本身 contribution 太弱
```

此时再考虑更换第二模块。

---

## 17. 如果 PCGrad 也无效

例如：

```text
Full-PCGrad:
Q <= 0.865
A <= 0.731
```

那么停止继续修 MSCM。

重新定义第二贡献方向，优先考虑：

```text
1. Image-Prompt Correspondence
2. Prompt-aware scoring
3. Task-specific prompt/adaptation
```

而不是继续设计复杂 cross-attention 或更多 similarity convolution。

---

## 18. MSCM 当前应该如何看待

目前 MSCM 还不能算“已经验证强有效”。

V12：

```text
R0 A = 0.7321
B2 A = 0.7328
```

只有：

```text
+0.0007
```

这个增益很小。

但 Full 相比 B1：

```text
A:
0.7269 -> 0.7309
```

仍有：

```text
+0.0040
```

因此 MSCM 值得在 gradient conflict 被解决后再做最终判断。

现在立刻换掉还太早。

V13 阶段不要同时：


```text

```

## 21. Contribution 定义

仍然只有两个主要贡献：

### Contribution 1

```text
DG-MPQ
Deviation-Guided Multi-Level Patch Quality Modeling
```

用于：

```text
Perceptual Quality
```

### Contribution 2

```text
MSCM
Multi-Level Semantic Correspondence Modeling
```

用于：

```text
Image-Text Alignment
```

PCGrad 只作为 optimization strategy，不包装成第三贡献。

## 23. 一句话总结

V13 不再继续盲目更换 Alignment 模块，而是针对 V12 中已经暴露出的 Shared-LoRA-level task interference：先测量 Quality 与 Alignment 在共享 LoRA 上的梯度余弦与冲突率；若冲突显著，则仅对 Shared LoRA 使用 PCGrad，而 DG-MPQ、MSCM 及各自 prediction branches 保持正常独立优化。目标是在保留 shared adaptation positive transfer 的同时减少 destructive gradient interference，使 Full 尽量同时保住 B1 的 Quality 优势和 MSCM 带来的 Alignment 增益。
