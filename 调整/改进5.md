# V9 改进方案：DG-MPQ + Text-Conditioned Attention Pooling

## 1. 当前结论

当前 V8 的核心结构为：

```text
CLIP ViT-B/16
+ Visual LoRA
+ DG-MPQ
+ HCMI-ViT
+ Task-Oriented Routing
+ Dual Regression Heads
```

多个 content split 的结果：

| Split | B1 Q-SRCC | Full Q-SRCC | B1 A-SRCC | Full A-SRCC |
|---|---:|---:|---:|---:|
| split3 | 0.8563 | 0.8555 | 0.7046 | 0.7193 |
| split4 | 0.8708 | 0.8634 | 0.7285 | 0.7207 |
| split5 | 0.8571 | 0.8556 | 0.6963 | 0.7004 |
| split6 | 0.8771 | 0.8747 | 0.7514 | 0.7471 |

平均约为：

```text
B1 Q-SRCC   ≈ 0.8653
Full Q-SRCC ≈ 0.8623

B1 A-SRCC   ≈ 0.7202
Full A-SRCC ≈ 0.7219
```

因此：

1. DG-MPQ 在不同 split 上较稳定，保留。
2. HCMI-ViT 对 Alignment 的增益不稳定，且经常伴随 Quality 下降。
3. V9 不继续修补 HCMI，而是重新设计 Alignment 分支。

---

## 2. 为什么放弃当前 HCMI-ViT

当前 HCMI 包含：

```text
H6 detail visual tokens
H12 semantic visual tokens
+ text tokens
→ prompt weighting
→ detail-level bidirectional cross-attention
→ semantic-level bidirectional cross-attention
→ two cross-modal MLPs
→ adaptive hierarchy gate
→ alignment residual
```

主要问题：

### 2.1 Alignment 更接近 correspondence，而不是 feature rewriting

当前 HCMI 做的是：

```text
V ← CrossAttn(V,T)
T ← CrossAttn(T,V)
```

但 Alignment 更直接的问题是：

> 文本描述的语义，在图像中是否存在对应区域？

因此更适合做：

```text
Text-conditioned visual retrieval / pooling
```

而不是多轮视觉与文本特征重写。

### 2.2 复杂交互最终仍被 mean pooling

前面进行了大量 patch-token interaction，最终却通过：

```python
V.mean(dim=1)
masked_mean_pool(T)
```

压成全局表示，可能丢掉细粒度 correspondence 信息。

### 2.3 数据规模较小

AGIQA-3K 总量约 3K。HCMI 包含 4 个 Cross-Attention、2 个 MLP、Prompt Gate、Hierarchy Gate 和多组 projection，自由度偏高，多 split 结果已经显示其收益不稳定。

---

## 3. V9 总体结构

```text
                    CLIP ViT-B/16
                          │
                     Visual LoRA
                          │
              ┌───────────┴───────────┐
              │                       │
           DG-MPQ                  TCAP
              │                       │
      Quality Modeling        Alignment Modeling
              │                       │
              ▼                       ▼
              v                    delta_a
              │                       │
              │              c = t0 + λa·delta_a
              │                       │
              ▼                       ▼
           [v,t0]                  [v,c]
              │                       │
       Quality Fusion          Alignment Fusion
              │                       │
        Quality Head            Alignment Head
```

职责：

```text
DG-MPQ → perceptual quality
TCAP   → image-text semantic correspondence
```

---

## 4. 新 Alignment 模块：TCAP

暂定名称：

**TCAP — Text-Conditioned Attention Pooling**

中文：**文本条件视觉注意力聚合**

设计思想受 IP-IQA image-prompt fusion 启发，并适配到 ViT patch token。

核心思想：

> 让文本表示作为 Query，直接从图像 patch 中检索与 prompt 最相关的视觉信息。

---

## 5. TCAP 输入

建议只使用：

```text
H12 patch tokens
+
global text representation t0
```

不再使用 H6 detail feature。

原因：Alignment 更依赖高层语义。对于诸如 “a red car beside a tree” 的 prompt，主要需要判断对象与语义关系是否匹配，H12 比中层纹理特征更直接。

---

## 6. 视觉投影

```python
h12_patch = hs[12][:, 1:, :]
V = visual_proj(h12_patch)
```

建议：

```python
self.visual_proj = nn.Sequential(
    nn.LayerNorm(768),
    nn.Linear(768, 256),
)
```

得到：

```text
V: [B,196,256]
```

---

## 7. 文本 Query

直接使用已有：

```text
t0 = base_text_proj(global_t)
```

shape：

```text
[B,256]
```

然后：

```python
Q = t0.unsqueeze(1)
```

得到：

```text
[B,1,256]
```

不再重新做复杂 prompt token weighting。

---

## 8. Text-Conditioned Attention Pooling

使用：

```text
Query = text representation
Key   = visual patch tokens
Value = visual patch tokens
```

即：

```python
z = cross_attention(
    query=Q,
    key=V,
    value=V,
)
z = z.squeeze(1)
```

得到：

```text
z: [B,256]
```

其含义是：

> 在当前 prompt 条件下，从图像中聚合出的最相关视觉语义表示。

---

## 9. 为什么只做 Text → Image

不再做双向：

```text
Visual queries Text
+
Text queries Visual
```

只保留：

```text
Text queries Visual
```

因为任务本身就是：

> 给定 prompt，检查图像是否符合 prompt。

因此信息流天然是：

```text
Prompt → 检索对应视觉区域
```

这比双向 interaction 更直接，也更轻量。

---

## 10. Correspondence Representation

获得：

```text
z  = prompt-conditioned visual representation
t0 = global text representation
```

后构造：

```python
r = torch.cat([
    z,
    t0,
    z * t0,
    torch.abs(z - t0),
], dim=-1)
```

shape：

```text
[B,1024]
```

含义：

```text
z            → prompt-relevant visual information
t0           → text semantics
z * t0       → element-wise consistency
|z - t0|     → element-wise mismatch
```

---

## 11. Correspondence MLP

```python
self.align_mlp = nn.Sequential(
    nn.Linear(dim * 4, dim),
    nn.GELU(),
    nn.Dropout(drop),
    nn.Linear(dim, dim),
    nn.LayerNorm(dim),
)
```

输出：

```text
delta_a: [B,256]
```

---

## 12. Alignment Residual

保留 outer residual：

```python
a_scale = torch.tanh(self.lambda_a)
c = t0 + a_scale * delta_a
```

这样 TCAP 不直接覆盖 CLIP 原始文本锚点。

如果 TCAP 暂时没学到有效信息，模型仍可退回：

```text
c ≈ t0
```

---

## 13. Task-Specific Fusion

V9 建议直接使用两套 fusion：

```python
h_q = quality_fusion(
    torch.cat([v, t0], dim=-1)
)

h_a = alignment_fusion(
    torch.cat([v, c], dim=-1)
)

q = quality_head(h_q)
a = align_head(h_a)
```

不再共享同一个 fusion。

只多一套：

```text
512 → 256
```

约增加 0.13M 参数，但能进一步减轻 Quality / Alignment 的梯度竞争。

---

## 14. DG-MPQ 完全保持不变

当前 DG-MPQ：

```text
H3 / H6 / H9 / H12
→ multi-level projection
→ local-global semantic deviation
→ deviation-guided patch weighting
→ quality residual
```

继续：

```python
v = v0 + torch.tanh(lambda_q) * delta_q
```

不修改 layer selection、patch weighting、semantic deviation、lambda_q 和 projection。

## 15. TCAP 参考实现

```python
class TCAP(nn.Module):

    def __init__(
        self,
        visual_width=768,
        dim=256,
        num_heads=4,
        drop=0.1,
    ):
        super().__init__()

        self.visual_proj = nn.Sequential(
            nn.LayerNorm(visual_width),
            nn.Linear(visual_width, dim),
        )

        self.attn = nn.MultiheadAttention(
            embed_dim=dim,
            num_heads=num_heads,
            dropout=drop,
            batch_first=True,
        )

        self.align_mlp = nn.Sequential(
            nn.Linear(dim * 4, dim),
            nn.GELU(),
            nn.Dropout(drop),
            nn.Linear(dim, dim),
            nn.LayerNorm(dim),
        )

    def forward(self, h12, t0):

        V = self.visual_proj(h12)
        Q = t0.unsqueeze(1)

        z, _ = self.attn(
            query=Q,
            key=V,
            value=V,
            need_weights=False,
        )

        z = z.squeeze(1)

        r = torch.cat([
            z,
            t0,
            z * t0,
            torch.abs(z - t0),
        ], dim=-1)

        return self.align_mlp(r)
```

## 16. model_v9.py 核心 Forward

```python
feat = backbone(x, input_ids, attention_mask)

v0 = heads.base_visual_proj(feat["global_v"])
t0 = heads.base_text_proj(feat["global_t"])

hs = feat["vision_hidden"]

# DG-MPQ
delta_q = dg_mpq(
    hs[3],
    hs[6],
    hs[9],
    hs[12],
)

v = v0 + torch.tanh(lambda_q) * delta_q

# TCAP
delta_a = tcap(
    hs[12][:, 1:, :],
    t0,
)

c = t0 + torch.tanh(lambda_a) * delta_a

# task-specific routing
h_q = quality_fusion(torch.cat([v, t0], dim=-1))
h_a = alignment_fusion(torch.cat([v, c], dim=-1))

q = quality_head(h_q)
a = align_head(h_a)

return torch.cat([q, a], dim=-1)
```

## 17. Loss 与 LoRA 暂时不改

第一阶段保持：

```text
Loss:
pure MSE

Visual LoRA:
q_proj + k_proj
r = 4
alpha = 8
dropout = 0

Text Encoder:
frozen
```

不要同时加入 PLCC Loss、Ranking Loss、Contrastive Loss 或更强 LoRA，避免无法判断 TCAP 本身是否有效。

## 23. 两个主要贡献

### Contribution 1 — DG-MPQ

**Deviation-Guided Multi-Level Patch Quality Modeling**

```text
multi-level ViT patch representation
+
local-global semantic deviation
+
adaptive patch weighting
```

用于：

```text
Perceptual Quality
```

### Contribution 2 — TCAP

**Text-Conditioned Attention Pooling for Semantic Correspondence**

```text
text as semantic query
+
ViT patch-level visual retrieval
+
explicit match / mismatch descriptor
```

用于：

```text
Image-Text Alignment
```

LoRA、Routing、Task-specific Fusion 和 Loss 都不额外包装成创新点。

## 25. 一句话总结

V9 不再继续修补复杂的 HCMI-ViT，而是将 Alignment 分支改为轻量的 Text-Conditioned Attention Pooling：使用文本全局语义作为 Query，从 ViT 高层 patch token 中直接聚合 prompt-relevant visual representation，并通过乘积与绝对差构造显式 correspondence descriptor；同时保留已验证较稳定的 DG-MPQ 作为 Quality 分支，从而形成更直接、轻量、任务职责清晰的双分支结构。
