# V17 最后一次模块验证方案：QARD — Quality-Aware Retrieval Decoder

> 当前参考 commit：`e6eb807168444fb0c170b50b1a8bf72da5181bf8`
>
> 当前最优真实模型仍是：
>
> ```text
> B1 / DG-MPQ only
> Q-SRCC = 0.8799
> A-SRCC = 0.7346
> joint  = 3.3809
> ```
>
> V16 DAPS：
>
> ```text
> B2-DAPS Q-SRCC = 0.8744
> Full    Q-SRCC = 0.8800
> ```
>
> 即：
>
> ```text
> B2 - R0  ≈ +0.0018

> ```
>
> 因此 DAPS 正式停止，不再做 V2/V3。
>

>
> **QARD — Quality-Aware Retrieval Decoder**
>
> 其核心借鉴 DEIQT 中已经被强消融验证的 Quality-Aware Decoder 思想，但不复制其 Attention Panel，也不做“多评审者”设计。
>

>
> ```text
> B1   = DG-MPQ only
> B2   = QARD only

> ```
>
> 如果：
>
> ```text
> Full Q-SRCC < B1 + 0.003
> ```
>
> 则正式停止寻找第二个神经网络模块，后续不再尝试新的 attention / decoder / pooling / fusion 模块。

# 1. 为什么最后选择 Quality-Aware Decoder

前面已经验证过：

```text
HCMI   → cross-modal cross-attention
TCAP   → global text query → patch attention
MSCM   → patch-text similarity map
MSRC   → global semantic relation
PTLC   → token-patch late interaction
DAPS   → patch score + patch importance
```

这些模块虽然覆盖了多种结构，但都没有形成与 DG-MPQ 稳定互补的增益。

剩余值得尝试的一类机制是：

> **不是重新聚合 patch，也不是重新预测 patch score，而是通过一个质量查询主动从 patch memory 中读取与当前图像质量判断最相关的信息。**

这对应 DEIQT 的核心 Quality-Aware Decoder。

DEIQT 自身消融中，真正主要的增益来自 decoder，而不是 Attention Panel：

```text
LIVEC:
ViT                  SRCC = 0.714
ViT + AP only        SRCC = 0.720
ViT + Decoder(CLS)   SRCC = 0.863
Full DEIQT           SRCC = 0.875

KonIQ:
ViT                  SRCC = 0.908
ViT + Decoder(CLS)   SRCC = 0.918
Full DEIQT           SRCC = 0.921
```

因此这次只借鉴最有实证支持的：

```text
quality query
→ one-layer cross-attention decoder
→ quality-aware representation
```

不采用其辨识度更高的 Attention Panel。

---

# 2. QARD 与 DG-MPQ 的职责必须明确不同

DG-MPQ：

```text
H3/H6/H9/H12
        ↓
Multi-Level Patch Representation
        ↓
Local-Global Deviation
        ↓
Deviation-Guided Aggregation
        ↓
delta_q
```

它的核心问题是：

> **哪些局部区域相对整体表现异常，以及这些区域应该怎样参与质量表征。**

QARD：

```text
H12 patches
        ↓
Patch Memory
        ↑
Dynamic Quality Query
        ↓
Cross-Attention Retrieval
        ↓
Query Refinement
        ↓
delta_d
```

它的核心问题是：

> **给定当前全局质量状态，模型应该主动从最终层 patch 中读取哪些证据来进一步修正质量表征。**

因此：

```text
DG-MPQ = bottom-up degradation aggregation

QARD   = top-down quality-aware retrieval
```

这是本次设计能否与 DG-MPQ 互补的理论基础。

---

# 3. 为什么不再做并联

前面的很多模块是：

```text
baseline feature ───┐
new module feature ─┼→ fusion
                    ↓
                  score
```

这种并联结构容易产生：

```text
信息重复
新模块覆盖 baseline
额外 fusion 重新学习
```

V17 改成**串联 refinement**：

```text
global visual feature
        ↓
DG-MPQ（可选）
        ↓
current quality query
        ↓
QARD（可选）
        ↓
refined quality visual feature
        ↓
与 text global feature fusion
        ↓
Q
```

因此 Full 中：

```text
DG-MPQ 先告诉 QARD：
“当前图像的质量状态是什么”

QARD 再从 H12 patch 中：
“主动读取与这个状态最相关的细节”
```

# 5. QARD 的三个阶段

QARD 设计成三个明确子步骤：

```text
1. Patch Memory Construction
        ↓
2. Dynamic Quality-Aware Retrieval
        ↓
3. Residual Query Refinement
```

---

# 6. Stage 1：Patch Memory Construction

输入只使用：

```text
H12: [B,197,768]
```

丢弃 CLS：

```python
patches = h12[:, 1:, :]
```

得到：

```text
[B,196,768]
```

经过：

```text
LayerNorm(768)
→ Linear(768,256)
→ GELU
```

得到：

$$
M\in\mathbb R^{196\times256}
$$

即：

```text
memory: [B,196,256]
```

为什么只用 H12：

```text
DG-MPQ 已经负责 multi-level。
QARD 只负责 final semantic patch retrieval。
```

避免两个贡献再次重叠。

---

# 7. Stage 2：Dynamic Quality Query

QARD 不使用固定 learnable query。

使用当前 Quality visual representation：

```text
v_q: [B,256]
```

构造动态 query：

$$
q_0=W_qv_q
$$

结构：

```text
LayerNorm(256)
→ Linear(256,256)
```

再：

```python
q = q0.unsqueeze(1)
```

得到：

```text
[B,1,256]
```

### B2-QARD

DG-MPQ 关闭：

```text
v_q = v0_q
```

因此 query 来自 global CLIP visual feature。

### Full

DG-MPQ 开启：

```text
v_q
=
v0_q
+
tanh(lambda_q) * delta_q
```

所以 Full 中 query 已经包含：

```text
multi-level degradation-aware information
```

这正是希望出现互补的地方。

---

# 8. 为什么不用 h_q 做 query

当前：

```text
h_q = Fusion(v_q, t_q)
```

已经混入文本。

如果 QARD 使用 `h_q`：

```text
text semantic
→ query
→ visual patch attention
```

会重新变成一种跨模态 interaction，和之前失败路线混淆。

因此 V17 使用：

```text
visual quality state v_q
```

作为 query。

文本仍只在后面的：

```text
quality_fusion([v_ref, t_q])
```

中参与。

# 9. Cross-Attention Retrieval

使用单层 Multi-Head Cross Attention：

$$
Q = W_Qq
$$

$$
K = W_KM
$$

$$
V = W_VM
$$

$$
A=
\operatorname{softmax}
\left(
\frac{QK^T}{\sqrt d}
\right)
$$

$$
r=AV
$$

参数：

```text
dim = 256
num_heads = 4
dropout = 0
```

实现建议：

```python
nn.MultiheadAttention(
    embed_dim=256,
    num_heads=4,
    dropout=0.0,
    batch_first=True,
)
```

# 10. Decoder Residual

先做 pre-norm：

```python
q_attn = self.norm_q(q)
m_attn = self.norm_m(memory)

attn_out, attn_weight = self.cross_attn(
    q_attn,
    m_attn,
    m_attn,
    need_weights=True,
    average_attn_weights=False,
)
```

然后：

$$
q_1=q+Attn(q,M)
$$

实现：

```python
q = q + attn_out
```

---

# 11. FFN Refinement

再使用：

```text
LayerNorm
→ Linear(256,512)
→ GELU
→ Linear(512,256)
```

即：

$$
q_2
=
q_1+
FFN(LN(q_1))
$$

这里使用：

```text
FFN ratio = 2
```

而不是原 Transformer 常见的 4。

原因：

```text
AGIQA-3K 数据量小；
仅需要一次轻量 refinement；
降低过拟合风险。
```

---

# 12. Decoder Output

最终：

```text
LayerNorm(256)
→ Linear(256,256)
→ GELU
→ LayerNorm(256)
```

输出：

```text
delta_d: [B,256]
```

这不是直接替换 `v_q`。

---

# 13. Outer Residual Gate

最终：

$$
v_{\mathrm{ref}}
=
v_q
+
\tanh(\lambda_d)\Delta_d
$$

其中：

```text
lambda_d init = 0.01
```

保持之前已经验证稳定的：

```text
strong baseline + gated residual
```

如果 Decoder 没用：

```text
lambda_d
```

可以维持很小。

---

# 14. 为什么不直接使用 Decoder output

如果直接：

```python
v_ref = decoder(...)
```

相当于让一个随机初始化的 0.7M 左右模块重写已有强 CLIP / DG-MPQ feature。

风险过高。

因此必须：

```text
baseline
+
small decoder residual
```

# 15. QARD 推荐实现

新增：

```text
v8/ipiqa/models/qard.py
```

建议第一版：

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class QARD(nn.Module):

    def __init__(
        self,
        width=768,
        dim=256,
        num_heads=4,
        ffn_ratio=2,
        drop=0.0,
    ):
        super().__init__()

        self.dim = dim

        # Stage 1: patch memory
        self.patch_memory = nn.Sequential(
            nn.LayerNorm(width),
            nn.Linear(width, dim),
            nn.GELU(),
        )

        # Stage 2: dynamic quality query
        self.query_proj = nn.Sequential(
            nn.LayerNorm(dim),
            nn.Linear(dim, dim),
        )

        self.norm_q = nn.LayerNorm(dim)
        self.norm_m = nn.LayerNorm(dim)

        self.cross_attn = nn.MultiheadAttention(
            embed_dim=dim,
            num_heads=num_heads,
            dropout=drop,
            batch_first=True,
        )

        hidden = int(dim * ffn_ratio)

        # Stage 3: decoder refinement
        self.norm_ffn = nn.LayerNorm(dim)

        self.ffn = nn.Sequential(
            nn.Linear(dim, hidden),
            nn.GELU(),
            nn.Linear(hidden, dim),
        )

        self.out = nn.Sequential(
            nn.LayerNorm(dim),
            nn.Linear(dim, dim),
            nn.GELU(),
            nn.LayerNorm(dim),
        )

        self._last_stats = None


    def forward(
        self,
        h12,
        v_q,
    ):
        # h12: [B,197,768]
        # v_q: [B,256]

        # --------------------------------
        # 1. Patch Memory Construction
        # --------------------------------

        memory = self.patch_memory(
            h12[:, 1:, :]
        )                                  # [B,196,256]

        # --------------------------------
        # 2. Dynamic Quality Query
        # --------------------------------

        q = self.query_proj(
            v_q
        ).unsqueeze(1)                     # [B,1,256]

        q_norm = self.norm_q(q)
        m_norm = self.norm_m(memory)

        attn_out, attn_weight = (
            self.cross_attn(
                q_norm,
                m_norm,
                m_norm,
                need_weights=True,
                average_attn_weights=False,
            )
        )

        q = q + attn_out

        # --------------------------------
        # 3. Residual Query Refinement
        # --------------------------------

        q = q + self.ffn(
            self.norm_ffn(q)
        )

        delta_d = self.out(
            q.squeeze(1)
        )                                  # [B,256]

        # attn_weight:
        # [B, heads, 1, 196]

        w = attn_weight.squeeze(2)          # [B,H,196]

        entropy = (
            -w
            * torch.log(
                w + 1e-8
            )
        ).sum(dim=-1)

        entropy_norm = (
            entropy
            / math.log(
                w.shape[-1]
            )
        )

        self._last_stats = {
            "attn_entropy":
                round(
                    entropy_norm.mean().item(),
                    4
                ),

            "attn_max":
                round(
                    w.max(
                        dim=-1
                    ).values.mean().item(),
                    4
                ),

            "decoder_norm":
                round(
                    delta_d.norm(
                        dim=-1
                    ).mean().item(),
                    4
                ),

            "memory_norm":
                round(
                    memory.norm(
                        dim=-1
                    ).mean().item(),
                    4
                ),
        }

        return delta_d
```

# 16. 为什么自己写一层 Decoder，而不是直接 `TransformerDecoderLayer`

可以直接用：

```python
nn.TransformerDecoderLayer
```

但自己展开更适合当前实验，因为可以记录：

```text
attention entropy
attention max
```

用于判断：

```text
QARD 是否真的形成 patch selection
```

而不是只知道最终分数没涨。

---

# 17. 注意：attention 不要求特别尖锐

196 个 patch 下，均匀注意力：

```text
每个 patch ≈ 1 / 196 ≈ 0.0051
```

归一化 entropy：

```text
≈ 1.0
```

如果长期：

```text
attn_entropy ≈ 1.0
attn_max ≈ 0.005
```

说明 Decoder 几乎只是平均池化。

如果：

```text
attn_entropy ≈ 0
attn_max ≈ 1
```

又说明极端 collapse。

比较合理的是：

```text
entropy 从接近 1
逐渐下降到 0.6~0.95 的某个稳定区域
```

但这个范围只用于诊断，不做硬约束。

# 24. V17 Quality forward

推荐：

```python
# =====================
# Quality branch
# =====================

v0_q = self.quality_visual_proj(
    global_v
)

# ---------------------
# Contribution 1: DG-MPQ
# ---------------------

if self.use_dg_mpq:

    delta_q = self.dg_mpq(
        hs[3],
        hs[6],
        hs[9],
        hs[12],
    )

    q_scale = torch.tanh(
        self.lambda_q
    )

    v_q = (
        v0_q
        +
        q_scale * delta_q
    )

    ratios["quality_ratio"] = (
        (q_scale * delta_q)
        .norm(dim=-1)
        .mean()
        /
        (
            v0_q.norm(
                dim=-1
            ).mean()
            + 1e-6
        )
    ).item()

else:

    v_q = v0_q


# ---------------------
# Contribution 2: QARD
# ---------------------

if self.use_qard:

    delta_d = self.qard(
        hs[12],
        v_q,
    )

    d_scale = torch.tanh(
        self.lambda_d
    )

    v_ref = (
        v_q
        +
        d_scale * delta_d
    )

    ratios["decoder_ratio"] = (
        (
            d_scale * delta_d
        )
        .norm(dim=-1)
        .mean()
        /
        (
            v_q.norm(
                dim=-1
            ).mean()
            + 1e-6
        )
    ).item()

else:

    v_ref = v_q


# ---------------------
# Existing text fusion
# ---------------------

t_q = self.quality_text_proj(
    global_t
)

h_q = self.quality_fusion(
    torch.cat(
        [v_ref, t_q],
        dim=-1,
    )
)

q = self.quality_head(
    h_q
)
```

# 39. 为什么只有一层 Decoder

DEIQT 自身实验已经说明：

```text
1 / 2 / 4 / 8 layers
```

性能差异很小。

而一层已经非常强。

当前 AGIQA-3K 更小，因此没有理由堆深度。

---

# 40. 为什么不加入 Attention Panel

DEIQT 的 AP 设计：

```text
multiple learned panel members
→ multiple predictions
→ mean
```

虽然有效，但：

1. 独立增益比 Decoder 小很多；
2. “评审团”概念辨识度较高；
3. 会让 V17 变成明显的 DEIQT 复刻；
4. 增加结构复杂度；
5. 当前只需要验证 decoder 核心机制。

所以这轮：

```text
只测试 QARD
```

# 49. 两个模块的逻辑关系

非常容易解释：

```text
DG-MPQ:
bottom-up
从局部异常构建质量表征

QARD:
top-down
利用当前质量表征重新查询视觉细节
```

即：

> **Bottom-up degradation modeling + Top-down quality-aware retrieval**

这比两个并列 patch weighting 模块清晰得多。

# 52. 最终一句话

V17 是第二模块路线的最后一次实验。

它不再：

```text
重新做 patch weighting
重新做 patch scoring
重新做 image-text alignment
```

而是采用一个经过 IQA 文献强消融支持、且与 DG-MPQ 建模方向不同的：

```text
Dynamic Quality Query
→ H12 Patch Memory
→ One-Layer Cross-Attention Retrieval
→ Residual Quality Refinement
```

最终只看一个问题：

> **DG-MPQ 提供的 bottom-up degradation-aware representation，能否通过 top-down Quality-Aware Decoder 进一步从 final visual patches 中检索到互补质量证据？**

如果 Full 仍无法稳定超过 B1 至少 `+0.003`，就接受实验事实：当前框架已经不适合继续堆第二模块。
