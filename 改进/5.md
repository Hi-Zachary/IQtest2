# AIGIQA-20K 迁移与三实验验证完整方案

> 项目：`Hi-Zachary/IQtest2`  
> 当前参考 commit：`939e72c8ea27a950db7b9b3840ebb42b8dfb3623`  
> 当前核心模型：V17 = CLIP ViT-B/16 + Visual LoRA + DG-MPQ + QARD  
>
> 本次目标不是重新设计模型，而是把同一套 V17 核心架构迁移到更大、更复杂的 AIGIQA-20K，验证：
>
> 1. AGIQA-3K 上模块增益偏小，是否主要由数据规模和 split 方差造成；
> 2. DG-MPQ 在更大数据上是否仍有稳定收益；
> 3. QARD 是否能在 DG-MPQ 基础上带来更稳定的互补增益。
>
> 第一阶段只跑 3 个并行实验：
>
> ```text
> R0   = Base CLIP + LoRA
> B1   = Base + DG-MPQ
> Full = Base + DG-MPQ + QARD
> ```
>
> 第一阶段不跑 QARD-only。当前最需要回答的是 `Full 是否稳定优于 B1`。

---

## 1. 为什么迁移到 AIGIQA-20K

当前 AGIQA-3K 只有约 2,982 张图、约 300 个 prompt。CLIP 本身已有很强的视觉/语义先验，因此复杂模块容易只带来 `0.00x` 的收益，并且这个量级和不同 split 的波动接近。

当前 QARD 的跨设置结果也体现了这一点：

```text
AGIQA-3K split5:  Full - B1 = +0.0054
AGIQA-3K split6:  Full - B1 = -0.0018
AIGCIQA2023:      Full - B1 = +0.0042
```

平均约 `+0.0026`。

AIGIQA-20K 更适合做稳定性验证：

```text
20,000 AIGC images
15 个生成模型
21 名受试者
420,000 条主观评分
```

而且数据生成时显式改变 CFG、迭代设置、输出分辨率等，因此分布明显更复杂。

## 2. AIGIQA-20K 与当前任务的标签协议差异

### 当前 AGIQA-3K

```text
image + prompt
      ↓
[Perceptual Quality, Alignment]
```

即两个独立回归目标：

```text
Q
A
```

### AIGIQA-20K

```text
image + prompt
      ↓
overall MOS
```

AIGIQA-20K 的 MOS 是一个综合主观质量分数，受试者评分时综合考虑 perceptual quality 和 text-image alignment，最终只保留一个 MOS。

因此迁移原则是：

```text
核心模型不改
输出/监督协议改成 single-score
```

第一阶段严禁同时修改：

```text
DG-MPQ
QARD
CLIP backbone
LoRA rank
hidden dim
learning rate
loss 类型
scheduler
attention heads
FFN ratio
```

只允许改：

```text
Dataset loader
single-score task
single-score output
official split
evaluation
config
```

## 7. Dataset 适配

修改：

```text
v8/ipiqa/datasets/agiqa_datasets.py
```

新增 single-score collator：

```python
class singlescore_collator:
    def __call__(self, batch):
        images, prompt, mos = zip(*batch)

        images = torch.stack(images)
        mos = torch.stack(mos).view(-1, 1)

        return {
            "images": images,
            "text": prompt,
            "score": mos,
        }
```

新增：

```python
class AIGIQA20K(Dataset):
    def __init__(self, data_info, transform, vis_root):
        super().__init__()

        self.vis_root = Path(vis_root)
        self.transform = transform
        self.data_info = data_info.reset_index(drop=True)

        self.collator = singlescore_collator()

    def __len__(self):
        return len(self.data_info)

    def __getitem__(self, index):
        row = self.data_info.iloc[index]

        image_name = row["name"]
        prompt = str(row["prompt"])
        mos = float(row["mos"])

        image = Image.open(
            self.vis_root / image_name
        ).convert("RGB")

        image = self.transform(image)

        return (
            image,
            prompt,
            torch.tensor(
                mos,
                dtype=torch.float32,
            ),
        )
```

这里推荐显式使用：

```python
row["name"]
row["prompt"]
row["mos"]
```

而不是 `iloc[:,0/1/2]`，防止 CSV 增加额外列后读取错位。

## 9. Training loss

第一轮继续纯 MSE：

```python
def iqa_loss(model, samples):
    x = samples["images"]
    y = samples["score"]
    text = samples["text"]

    pred = model(x, text)

    loss = nn.MSELoss()(pred, y)

    return loss, {
        "loss": loss.detach().clone()
    }
```

不要第一轮换成：

```text
MAE
rank loss
PLCC loss
pairwise loss
MNL loss
```

否则无法判断增益到底来自数据规模还是 loss。

## 11. AIGIQA-20K / NTIRE 官方 Main Score

NTIRE 2024 Image Track 使用：

$$
\mathrm{MainScore}
=
\frac{
|\mathrm{SRCC}| + |\mathrm{PLCC}|
}{2}
$$

因此建议：

```python
main_score_raw = (
    abs(srcc)
    +
    abs(plcc_raw)
) / 2
```

---

## 12. PLCC 的官方协议差异

NTIRE 2024 challenge protocol 在计算 PLCC 前进行三阶多项式非线性回归。

你当前 AGIQA evaluator 是直接：

```python
pearsonr(pred, mos)
```

所以为了和 AIGIQA-20K / NTIRE 报告规范对齐，建议同时计算：

```text
PLCC_raw
PLCC_mapped
```

可实现：

```python
coef = np.polyfit(
    pred,
    mos,
    deg=3,
)

pred_mapped = np.polyval(
    coef,
    pred,
)

plcc_mapped = pearsonr(
    pred_mapped,
    mos,
)[0]
```

然后：

$$
\mathrm{MainScore}_{official}
=
\frac{
|\mathrm{SRCC}|
+
|\mathrm{PLCC}_{mapped}|
}{2}
$$

注意：

```text
polynomial mapping 只用于 evaluation
不参与训练
```

推荐最终报告：

```text
SRCC
PLCC_raw
PLCC_mapped
KRCC
MainScore_raw
MainScore_official
```

## 14. 为什么当前 V17 的 Q branch 可以直接预测 AIGIQA-20K MOS

当前 V17 Q branch：

```text
global_v
   ↓
DG-MPQ
   ↓
QARD
   ↓
v_ref
   │
   ├──── global_t
   │        │
   └─ concat
        ↓
quality_fusion
        ↓
quality_head
```

所以它本来就同时使用：

```text
视觉信息
+
prompt 语义信息
```

这与 AIGIQA-20K 的综合 MOS 定义是相容的。

第一轮不要把原 Alignment head 再融合回来，不要设计：

```text
overall = αQ + βA
```

也不要新建：

```text
[q_feature, a_feature] -> overall fusion
```

否则又引入了一个新模型变量。

## 15. V17 增加 `single_score`

在 `model_v17.py`：

```python
def __init__(
    ...,
    single_score=False,
):
    ...
    self.single_score = single_score
```

然后在 Q branch 得到：

```python
q = self.quality_head(h_q)
```

之后直接：

```python
if self.single_score:
    self._last_ratios = ratios
    return q
```

再进入原 Alignment branch。

这样 AIGIQA-20K 下：

```text
Alignment branch 不 forward
不训练
不耗额外计算
```

`from_config()` 增加：

```python
single_score=cfg.get(
    "single_score",
    False,
)
```

AGIQA-3K 旧配置不受影响。

```text

median

>77 token 占比
```

## 31. 第一轮最关键的两个增益

定义：

$$
\Delta_{\mathrm{DG}}
=
S_{\mathrm{B1}}
-
S_{\mathrm{R0}}
$$

$$
\Delta_{\mathrm{QARD}}
=
S_{\mathrm{Full}}
-
S_{\mathrm{B1}}
$$

优先看：

```text
SRCC
```

同时检查：

```text
PLCC
MainScore
```

---

## 32. DG-MPQ 判定标准

如果：

```text
B1 - R0 < +0.002
```

说明即使在 20K 数据上 DG-MPQ 也只有很小边际收益，需要重新审视核心方法。

如果：

```text
+0.002 ~ +0.006
```

说明有稳定作用，但仍属于强 baseline 场景。

如果：

```text
>= +0.006
```

认为 DG-MPQ 有明显价值。

如果：

```text
>= +0.010
```

非常理想，说明 AGIQA-3K 很可能确实限制了模块发挥空间。

---

## 33. QARD 判定标准

最关键：

```text
Full - B1
```

如果：

```text
<= +0.001
```

彻底停止 QARD，不再调 heads / FFN / H9 / gate。

如果：

```text
+0.001 ~ +0.003
```

边缘，不建议马上包装成第二贡献。

如果：

```text
+0.003 ~ +0.006
```

可以保留，说明 QARD 与 DG-MPQ 有稳定互补性。

如果：

```text
>= +0.006
```

很有价值。

如果：

```text
>= +0.010
```

可以较明确地认为：AGIQA-3K 的小规模/高方差掩盖了 QARD 的真实作用。

### 情况 A：理想

```text

```

```text

```

```text
B2-QARD
正式消融
```

### 情况 B：DG 强，QARD 弱

```text
B1 - R0 >= +0.006
Full - B1 <= +0.001
```

保留 DG-MPQ，删除 QARD。

### 情况 C：两者仍只有 0.00x

例如：

```text
R0   .830
B1   .833
Full .834
```

说明即使 14K 训练样本，复杂模块边际贡献仍然很小。此时停止继续设计第二模块。

### 情况 D：Full 下降

直接认定 QARD 缺乏稳定价值，不做 QARD-V2。

## 45. 本次迁移的核心原则

这不是：

```text
“为 AIGIQA-20K 重做一套网络”
```

而是：

```text
同一个 V17 核心模型
        ↓
适配 single overall MOS protocol
        ↓
在更大、更复杂的 20K benchmark 上
验证模块真实增益
```

第一轮严格只跑：

```text
R0
B1 = DG-MPQ
Full = DG-MPQ + QARD
```

三组。

真正需要回答的只有两个问题：

$$
\Delta_{\mathrm{DG}}
=
S_{\mathrm{B1}}
-
S_{\mathrm{R0}}
$$

$$
\Delta_{\mathrm{QARD}}
=
S_{\mathrm{Full}}
-
S_{\mathrm{B1}}
$$

如果在 AIGIQA-20K 上 DG-MPQ 的提升明显扩大，而且 QARD 能稳定再带来至少约 `+0.003`，就有较强证据说明此前 AGIQA-3K 的小规模和 split variance 确实压缩了复杂模块的发挥空间。

如果 Full 相比 B1 仍只有约 `+0.001`，则停止 QARD 路线，不再为第二模块继续调结构。
