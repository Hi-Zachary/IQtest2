# V16 改进方案：DAPS — Dual-Branch Adaptive Patch Scoring

> 当前参考代码：`v15`
>
> 当前参考 commit：`545cf6336ddb02f9607792861e5128417176da34`
>
> 目标：停止继续设计新的 Alignment representation module。保留已经验证有效的 DG-MPQ，并尝试一个来自成熟 IQA 路线、但与 DG-MPQ 职责不同的第二模块：
>
> **DAPS — Dual-Branch Adaptive Patch Scoring**
>
> 核心思想参考 MANIQA / patch-wise IQA prediction 的成熟做法，但不照搬整套 MANIQA，也不使用其 TAB/SSTB。只保留经过 IQA 长期验证的：
>
> ```text
> patch feature
> ├─ Score Branch      → 每个 patch 的局部质量分数
> └─ Importance Branch → 每个 patch 对整体主观评分的重要性
>            ↓
>     Patch-wise Weighted Prediction
>            ↓
>     Residual Global Calibration
> ```
>
> V16 的第二模块不再负责 Alignment。Alignment 继续使用当前强 CLIP baseline。
>
> 第一轮只跑 **3 个并行实验**：
>
> ```text
> B1-V16   = DG-MPQ only
> B2-V16   = DAPS only
> Full-V16 = DG-MPQ + DAPS
> ```
>
> R0 不重新跑，直接复用 V15 matched-init baseline：
>
> ```text
> R0-V15:
> Q-SRCC = 0.8726
> A-SRCC = 0.7377
> joint  = 3.3747
> ```
>
> 这样一次实验就能判断：
>
> 1. DAPS 自己是否有效；
> 2. DAPS 与 DG-MPQ 是否互补；
> 3. Full 是否能超过 DG-MPQ 单模块。

---

# 1. 为什么这次不再做 Alignment 模块

当前已经连续验证过：

```text
HCMI  → cross-attention
TCAP  → global-query patch attention
MSCM  → patch-text similarity map
MSRC  → global semantic relation
PTLC  → token-patch late interaction
```

它们都没有稳定超过强 CLIP Alignment baseline。

V15 的 PTLC 甚至已经证明：

```text
模块正常训练
token weight 无 collapse
alignment residual 非 0
```

但 controlled result 仍然：

```text
R0 A-SRCC      = 0.7377
B2-PTLC A-SRCC = 0.7364
```

因此不再继续第六个 Alignment encoder。

---

# 2. 为什么尝试 Patch-wise Prediction

传统和现代 NR-IQA 中，patch-wise prediction 是非常成熟的设计。

MANIQA 的最终预测模块就是一个典型的双分支结构：

```text
Patch Feature
     │
 ┌───┴────────┐
 │            │
Score       Weight
Branch      Branch
 │            │
s_i          w_i
 └─────┬──────┘
       │
   Σ w_i s_i
       │
  Image Quality
```

其逻辑是：

> 一幅图像不同区域的局部质量不同，同时不同区域对人类最终主观评分的贡献也不同。

这与当前 DG-MPQ 的职责并不一样。

---

# 3. DG-MPQ 与 DAPS 的职责区分

当前 DG-MPQ：

```text
Multi-Level Patch
      ↓
Local-Global Semantic Deviation
      ↓
Deviation-Guided Patch Weight
      ↓
Weighted Feature Aggregation
      ↓
Quality Residual Feature
```

它回答：

> 哪些局部区域相对整体语义更加异常？  
> 应该怎样聚合视觉表征？

DAPS 则回答：

```text
Patch Feature
      ↓
 ┌────┴─────┐
 │          │
Patch      Patch
Score    Importance
 │          │
 └────┬─────┘
      ↓
Image-level Patch Score
      ↓
Global Prediction Calibration
```

它回答：

> 每个 patch 自己的质量分数是多少？  
> 每个 patch 对整体主观评分有多重要？

因此：

```text
DG-MPQ = representation-level modeling
DAPS   = prediction-level modeling
```

这比再设计一个新的 visual feature aggregation 模块更容易形成两个清晰、平级的贡献。

# 4. V16 总体结构

```text
                           CLIP ViT-B/16
                                │
                           Visual LoRA
                                │
                 ┌──────────────┴──────────────┐
                 │                             │
              Quality                       Alignment
                 │                             │
          Global Feature                 Global V/T
                 │                             │
        ┌────────┴─────────┐                   │
        │                  │                   │
     DG-MPQ              DAPS             CLIP Baseline
        │                  │                   │
   delta_q             delta_score             A
        │                  │
        └───── Quality Fusion ─────┐
                                   │

```

更具体：

```text
Quality baseline:
global_v + global_t
        ↓
quality fusion
        ↓
q_base

DG-MPQ:
H3/H6/H9/H12
        ↓
delta_q feature
        ↓

DAPS:
H12 patch tokens
        ↓
patch score + patch importance
        ↓
q_patch
        ↓
residual scalar calibration

Final:
q = q_base_or_DG + tanh(lambda_p) * delta_patch
```

# 5. 第一版为什么只使用 H12 patch

DAPS 第一版**不要再做 multi-level**。

原因：

```text
DG-MPQ 已经明确负责 multi-level H3/H6/H9/H12。
```

如果 DAPS 也做多层融合，两点创新会重新重叠。

因此 DAPS 第一版只使用：

```text
H12 patch tokens
```

即：

```text
[B,196,768]
```

DAPS 强调的是：

```text
patch-wise prediction
```

而不是：

```text
multi-level representation
```

---

# 6. DAPS 三个阶段

DAPS 设计成完整但不复杂的三阶段：

```text
1. Patch Quality Encoding
        ↓
2. Dual-Branch Score-Importance Estimation
        ↓
3. Distribution-Aware Global Calibration
```

这样完整度和 DG-MPQ 基本平衡。

---

# 7. Stage 1：Patch Quality Encoding

输入：

```text
H12: [B,197,768]
```

去掉 CLS：

```python
patch = h12[:, 1:, :]
```

投影：

```text
LayerNorm(768)
→ Linear(768,256)
→ GELU
```

得到：

```text
P: [B,196,256]
```

建议第一版：

```text
dim = 256
dropout = 0
```

---

# 8. Stage 2：Dual-Branch Score-Importance Estimation

## 8.1 Patch Score Branch

每个 patch 预测一个局部质量 latent score：

$$
s_i=f_s(P_i)
$$

结构：

```text
Linear(256,128)
→ GELU
→ Linear(128,1)
```

得到：

```text
score: [B,196,1]
```

第一版不要 sigmoid。

原因：

> 局部 quality score 只是 latent scalar，不必强制限制到 $[0,1]$。

---

# 9. Patch Importance Branch

每个 patch 预测一个对整体评分的相对重要性：

$$
a_i=f_w(P_i)
$$

结构：

```text
Linear(256,128)
→ GELU
→ Linear(128,1)
```

之后使用 softmax：

$$
w_i=
\frac{
e^{a_i}
}{
\sum_j e^{a_j}
}
$$

实现：

```python
weight = F.softmax(
    weight_logits,
    dim=1,
)
```

这样：

```text
Σ_i w_i = 1
```

比 sigmoid 后再除和更加自然。

---

# 10. Patch-wise Quality Prediction

计算：

$$
q_{\mathrm{patch}}
=
\sum_i w_i s_i
$$

实现：

```python
q_patch = (
    weight * score
).sum(dim=1)
```

得到：

```text
[B,1]
```

这就是最核心的 MANIQA-style patch-weighted prediction。

---

# 11. 为什么还需要 Stage 3

如果直接：

```text
q = q_patch
```

风险较大。

当前 global CLIP + LoRA baseline 已经很强：

```text
Q-SRCC ≈ 0.873
```

所以 DAPS 不应该替换 global prediction，而应该提供局部质量证据。

因此加入：

# Distribution-Aware Global Calibration

---

# 12. Patch Score Distribution Statistics

从局部 score 分布提取：

```text
weighted mean  = q_patch
mean           = score_mean
std            = score_std
minimum        = score_min
maximum        = score_max
weight entropy = weight_entropy
```

其中：

$$
H(w)
=
-\sum_iw_i\log(w_i+\epsilon)
$$

这些统计反映：

```text
整体局部评分水平
局部质量波动
最坏区域
最好区域
预测是否集中在极少 patch
```

---

# 13. Global Calibration Descriptor

加入当前 global quality representation：

```text
h_q: [B,256]
```

构造：

```text
[
h_q,
q_patch,
score_mean,
score_std,
score_min,
score_max,
weight_entropy
]
```

总维度：

```text
256 + 6 = 262
```

经过：

```text
Linear(262,128)
→ GELU
→ Linear(128,1)
```

得到：

$$
\Delta q_{\mathrm{patch}}
$$

---

# 14. Residual Scalar Calibration

最终：

$$
q_{\mathrm{final}}
=
q_{\mathrm{base}}
+
\tanh(\lambda_p)
\Delta q_{\mathrm{patch}}
$$

其中：

```text
lambda_p init = 0.01
```

和 DG-MPQ 的 residual 思路保持一致：

```text
strong baseline
+
small learnable correction
```

如果 DAPS 没有帮助：

```text
lambda_p
可以维持在接近 0
```

避免直接破坏现有强 Q baseline。

# 17. DAPS 推荐代码文件

新增：

```text
v8/ipiqa/models/daps.py
```

推荐实现：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class DAPS(nn.Module):
    def __init__(
        self,
        width=768,
        dim=256,
        hidden=128,
    ):
        super().__init__()

        self.patch_encoder = nn.Sequential(
            nn.LayerNorm(width),
            nn.Linear(width, dim),
            nn.GELU(),
        )

        self.score_branch = nn.Sequential(
            nn.Linear(dim, hidden),
            nn.GELU(),
            nn.Linear(hidden, 1),
        )

        self.weight_branch = nn.Sequential(
            nn.Linear(dim, hidden),
            nn.GELU(),
            nn.Linear(hidden, 1),
        )

        self.calibration = nn.Sequential(
            nn.Linear(dim + 6, hidden),
            nn.GELU(),
            nn.Linear(hidden, 1),
        )

        self._last_stats = None


    def forward(
        self,
        h12,
        h_q,
    ):
        # h12: [B,197,768]
        # h_q : [B,256]

        P = self.patch_encoder(
            h12[:, 1:, :]
        )                                  # [B,196,256]

        score = self.score_branch(P)        # [B,196,1]

        weight_logits = self.weight_branch(P)

        weight = F.softmax(
            weight_logits,
            dim=1,
        )                                   # [B,196,1]

        q_patch = (
            weight * score
        ).sum(
            dim=1
        )                                   # [B,1]

        score_mean = score.mean(
            dim=1
        )

        score_std = score.std(
            dim=1,
            unbiased=False,
        )

        score_min = score.min(
            dim=1
        ).values

        score_max = score.max(
            dim=1
        ).values

        weight_entropy = (
            -weight
            * torch.log(
                weight + 1e-8
            )
        ).sum(
            dim=1
        )                                   # [B,1]

        descriptor = torch.cat([
            h_q,
            q_patch,
            score_mean,
            score_std,
            score_min,
            score_max,
            weight_entropy,
        ], dim=-1)                          # [B,262]

        delta_q = self.calibration(
            descriptor
        )                                   # [B,1]

        self._last_stats = {
            "patch_score_mean":
                round(score_mean.mean().item(), 4),

            "patch_score_std":
                round(score_std.mean().item(), 4),

            "weight_entropy":
                round(weight_entropy.mean().item(), 4),

            "weight_max":
                round(
                    weight.max(
                        dim=1
                    ).values.mean().item(),
                    4,
                ),

            "q_patch":
                round(q_patch.mean().item(), 4),

            "delta_q":
                round(delta_q.abs().mean().item(), 4),
        }

        return delta_q
```

# 18. 一个重要设计选择：DAPS 不复用 DG-MPQ 的 patch weight

不要写成：

```text
DG-MPQ weight
→ DAPS
```

原因：

如果 DAPS 直接使用 DG-MPQ 的 patch weight：

```text
B2-DAPS
```

就无法独立存在。

同时两个贡献也会变成强耦合。

因此：

```text
DG-MPQ:
自己的 deviation-guided weight

DAPS:
自己的 prediction importance weight
```

二者概念不同、参数独立。

---

# 19. 为什么 DAPS 使用 H12，而 DG-MPQ 使用多层

这是刻意设计的职责分工。

DG-MPQ：

```text
H3/H6/H9/H12
→ multi-level degradation representation
```

DAPS：

```text
H12
→ semantically mature patch feature
→ score / importance prediction
```

这样避免：

```text
两个模块都在做 multi-level feature fusion
```

# 25. Quality forward 修改

```python

    torch.cat(
        [v_q, t_q],
        dim=-1
```

```python

    torch.cat(
        [v_q, t_q],
        dim=-1
    )
)

q_base = self.quality_head(h_q)


if self.use_daps:

    delta_patch = self.daps(
        hs[12],
        h_q,
    )

    p_scale = torch.tanh(
        self.lambda_p
    )

    q = (
        q_base
        +
        p_scale * delta_patch
    )

    ratios["patch_pred_ratio"] = (
        (p_scale * delta_patch)
        .abs()
        .mean()
        /
        (q_base.abs().mean() + 1e-6)
    ).item()

else:

    q = q_base
```

# 52. 两个最终贡献怎么讲

## Contribution 1：DG-MPQ

**Deviation-Guided Multi-Level Patch Quality Modeling**

```text
Multi-Level Patch Representation
        ↓
Local-Global Semantic Deviation
        ↓
Deviation-Guided Aggregation
        ↓
Quality Representation
```

解决：

> AIGC 图像中局部视觉异常相对整体内容的偏离。

---

## Contribution 2：DAPS

**Dual-Branch Adaptive Patch Scoring**

```text
Patch Quality Encoding
        ↓
Score / Importance Dual Prediction
        ↓
Distribution-Aware Global Calibration
        ↓
Image Quality Score
```

解决：

> 不同区域不仅质量程度不同，对最终人类主观评分的重要性也不同。

---

# 53. 两个模块的关系

一句话：

> DG-MPQ 决定“怎么看局部质量”，DAPS 决定“怎样把局部质量转化为最终主观评分”。

英文可以概括：

```text
DG-MPQ focuses on degradation-aware representation,
while DAPS focuses on patch-wise subjective quality prediction.
```

---

# 54. Alignment 怎么解释

不要再强行包装 Alignment 创新模块。

可以直接说：

> 对 image-text alignment，我们发现 CLIP 原始跨模态语义空间已经具有较强的对齐判别能力。相比额外复杂的交互模块，保留轻量 global cross-modal regression 在小规模 AGIQA 数据上更加稳定。

这反而符合真实实验。
