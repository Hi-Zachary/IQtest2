# AIGIQA-20K 无 LoRA 基线补跑方案（20 Epoch）

> 目的：补齐当前 V26 实验中的“**不用 LoRA**”基线。  
> 由于现有 B0 并不是纯 CLIP，而是：
>
> ```text
> CLIP ViT-B/16
> + Visual Q/K LoRA
> + 可训练 regression head
> ```
>
> 因此需要补一组：
>
> ```text
> Frozen CLIP
> + 相同的 regression head
> + 不使用 LoRA
> ```
>
> 从而验证：
>
> > 在 **相同 head / 相同训练协议** 下，Visual Q/K LoRA 是否真的有贡献。

---

## 1. 现有实验链与缺失项

当前已有四组：

```text
B0  LoRA Baseline        = CLIP + Q/K LoRA
B1  LoRA + LQEA
B2  LoRA + CSAE
B3  LoRA + LQEA + CSAE
```

其中 B0 已经不是“真正不带适配的 baseline”，因为它包含：

- Visual Q/K LoRA
- 可训练 projection / fusion / head

所以现在缺的其实是：

```text
F0  Frozen-Head Baseline
    = Frozen CLIP
    + same projection / fusion / head
    + no LoRA
    + no LQEA
    + no CSAE
```

补完后，完整逻辑链是：

```text
F0  Frozen CLIP + head
        │
        │ + Visual Q/K LoRA
        ▼
B0  LoRA Baseline
     /        \
 +LQEA       +CSAE
   │            │
   ▼            ▼
  B1            B2
     \          /
      \        /
         B3
        Full
```

## 3. F0 的准确结构

F0 不是“纯 CLIP cosine baseline”。

F0 应该是：

```text
Image + Prompt
      ↓
Frozen CLIP ViT-B/16
      ↓
global_v, global_t
      ↓
visual_proj(global_v) = v0
text_proj(global_t)   = t0
      ↓
concat([v0, t0, zeros])
      ↓
overall_fusion
      ↓
overall_head
      ↓
Overall MOS
```

也就是说：

### F0 可训练部分

- `visual_proj`
- `text_proj`
- `overall_fusion`
- `overall_head`

### F0 冻结部分

- CLIP visual backbone
- CLIP text encoder

### F0 不存在

- LoRA
- LQEA
- CSAE

---

## 4. 与 B0 的唯一差别

F0 与 B0 唯一有效差别应该是：

```yaml
use_lora: false
```

并保持：

```yaml
use_lqea: false
use_csae: false
```

所以：

### B0

```text
CLIP + Q/K LoRA + same head
```

### F0

```text
Frozen CLIP + same head
```

这就保证比较的唯一问题是：

> 是否需要 Visual Q/K LoRA。

## 7. 关键问题：初始化必须公平

这里最容易犯错。

因为 B0 有 `use_lora=True`，F0 有 `use_lora=False`。  
如果只是简单地：

```text
seed = 42
重新 new 一个模型
```

那么由于模型构造路径不同，后面这些层的随机初始化不一定相同：

- `visual_proj`
- `text_proj`
- `overall_fusion`
- `overall_head`

这会导致：

> F0 vs B0 不再只是“有没有 LoRA”的差别。

因此需要做 **matched initialization**。

---

## 8. Matched Initialization 方案

建议生成一个专门的初始化 ckpt：

```text
init_ckpt/v26_f0_matched_seed42.pth
```

### 推荐做法

1. 先构建一个 F0 模型：

```python
model_f0 = LACEAIGIQA20K(
    use_lora=False,
    use_lqea=False,
    use_csae=False,
    ...
)
```

2. 读取当前 B0/B1/B2/B3 所使用的初始化文件：

```text
init_ckpt/v26_aigiqa20k_seed42.pth
```

3. 从中复制以下共享参数到 F0：

```text
visual_proj.*
text_proj.*
overall_fusion.*
overall_head.*
```

4. 保存为：

```text
init_ckpt/v26_f0_matched_seed42.pth
```

### 注意

不要尝试把整个带 LoRA wrapper 的 state_dict 生硬地完整 load 到 no-LoRA 模型。

只复制：

- key 相同
- shape 相同
- 且确实是共享结构

的参数即可。

## 9. 训练前必须做的 sanity check

在开始正式训练之前，必须验证：

> F0 与 B0 在初始时只有 LoRA 这一项差别。

### 要求检查

使用同一个 mini-batch，比较 F0 与 B0 初始输出：

$$
\max |\hat y_{F0} - \hat y_{B0}|
$$

由于：

- B0 的 LoRA 初始 residual 应接近 0
- F0 与 B0 的 head/projection 初始化一致

所以期望：

```text
max_abs_diff < 1e-6
```

如果明显不满足，不能直接训练，必须先检查：

1. `visual_proj` 是否一致
2. `text_proj` 是否一致
3. `overall_fusion` 是否一致
4. `overall_head` 是否一致
5. CLIP backbone 是否来自同一 ckpt
6. B0 的 LoRA 初始 residual 是否为零
7. eval / train mode 是否一致

## 10. F0 的梯度检查

F0 训练前/第一步训练后需检查：

### Frozen 的部分

```text
CLIP visual backbone grad = 0
CLIP text encoder grad = 0
```

### Trainable 的部分

```text
visual_proj grad > 0
text_proj grad > 0
overall_fusion grad > 0
overall_head grad > 0
```

### LoRA

```text
No trainable LoRA params
```

也就是说：

> F0 仍然能训练，但训练的是“回归头”，而不是 CLIP backbone。

## 13. 选择标准

仍然只使用：

```text
Validation MainScore
```

选 best checkpoint。

其中：

$$
\text{MainScore} = \frac{|\text{SRCC}| + |\text{PLCC}_{mapped}|}{2}
$$

先看 Validation，Test 只作为最终参考。

---

## 14. 需要比较的核心结果

当前已有 B0（LoRA Baseline）：

- Val SRCC = `0.8522`
- Val MainScore = `0.8782`

因此 F0 跑完后，核心比较只有：

### Validation

$$
\Delta SRCC_{LoRA} = SRCC_{B0} - SRCC_{F0}
$$

$$
\Delta MainScore_{LoRA} = MainScore_{B0} - MainScore_{F0}
$$

### Test（仅参考）

也可以看同样的差值，但不作为主要决策依据。

---

## 15. LoRA 有效性判定标准

### 情况 A：LoRA 明确有效

如果在 Validation 上满足：

$$
\Delta SRCC_{LoRA} \ge 0.002
$$

或

$$
\Delta MainScore_{LoRA} \ge 0.002
$$

并且另一指标不明显下降，则认为：

> Visual Q/K LoRA 有效，应保留。

---

### 情况 B：LoRA 略有效但较弱

如果：

```text
0 < ΔMainScore < 0.002
```

且 SRCC 也是轻微正增益，那么可以认为：

> LoRA 有一定作用，但不是很强。

这种情况下仍然可以保留 LoRA，但论文里不要把它写成“大创新模块”，而应写成：

> lightweight visual adaptation

---

### 情况 C：几乎没差别

如果：

```text
|ΔSRCC| < 0.001
|ΔMainScore| < 0.001
```

那么说明：

> LoRA 在 AIGIQA-20K 上贡献很弱。

此时就要认真考虑是否保留 LoRA。

---

### 情况 D：F0 更好

如果出现：

```text
F0 > B0
```

并且优势超过大约 `0.002`，则说明：

> 当前 Q/K LoRA 在该数据集上没有得到支持。

这时优先考虑删除 LoRA，而不是继续调 rank / target。

## 17. 论文中的方法定位

如果最终结果是 `B0 > F0`，那么方法定位可以写成：

```text
Frozen CLIP
   ↓
Lightweight visual adaptation (Q/K LoRA)
   ↓
Shared AIGC-IQA representation
   ├── LQEA
   └── CSAE
   ↓
Overall MOS prediction
```

其中：

- **LoRA**：基础适配策略
- **LQEA / CSAE**：核心功能模块

也就是说，LoRA 不一定作为主要创新点，但它是合理的 backbone adaptation。
